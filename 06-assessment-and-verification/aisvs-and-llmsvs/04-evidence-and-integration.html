前三章講「標準是什麼」。這一章回到你真正要做的事：手上有個系統，怎麼用這些標準驗證它，並產出別人能複查的證據？你會學到怎麼選目標層級、怎麼把一條需求變成一項驗證、證據要長什麼樣、AISVS 和 LLMSVS 以及其他文件怎麼分工，並用兩個虛構情境練習。

4.1 先選目標層級、再選要用的標準

順序很重要。LLMSVS v2.1 草稿明說「在測試前先選層級」，AISVS 也說依風險輪廓選。實務上可以分三步（以下流程是作者整理，非官方，但每一步的規則都出自官方文字）：

  1. 盤點系統有哪些功能：只是呼叫雲端模型的聊天介面？有檢索？有工具與 MCP？自己訓練或託管模型？功能決定哪些章會用到（草稿的適用標籤、AISVS 的 C8 / C9 / C10 就是這個邏輯）。
  2. 依風險輪廓選層級：內部工具、低風險 → 層級 1；面向客戶、處理個資 → 層級 2（AISVS 說多數正式系統至少層級 2）；關鍵或受高度監管 → 層級 3。
  3. 選標準：範圍橫跨代理、MCP、資料與基礎設施 → AISVS 較合適；系統是以 LLM 為核心的應用、需要較短的目錄 → LLMSVS 的 70 條較易上手。兩者並用時各自標明版本與層級，並明白兩者的需求編號不通用。

4.2 把一條需求變成驗證與證據

4.4 情境範例 A：客服 LLM 上線前，怎麼選層級並蒐證

情境 A（虛構）：潮汐電信的客服助理

虛構 潮汐電信（虛構）要在下個月上線客服助理：使用者登入後可詢問帳單；助理會檢索內部手冊與使用者自己的帳單資料，並能呼叫「申請退款」工具（上限由後端核准）。合規部門要求上線前提交「可被稽核的驗證報告」。資安新人要決定用 AISVS 還是 LLMSVS、目標層級與要蒐的證據。

  1. 盤點功能：有檢索（C8）、有工具呼叫（C9）、處理個資、用雲端模型 API；沒有自訓模型。所以訓練資料與模型生命週期的章可標不適用（需寫理由）。
  2. 選層級：面向客戶、處理個資 → 層級 2。AISVS 說多數正式系統至少層級 2。新人要在報告寫明這個選擇與理由，並寫明對「層級 2 是否包含層級 1」的解讀（官方未明說，見第 2 章）。
  3. 選標準：因為有 C9 的工具授權與 C5 的檢索授權議題，選 AISVS 1.01 較完整，並在報告用 v1.01-C5.2.2、v1.01-C9.5.3 這種格式引用。一般登入與工作階段安全另依 ASVS。
  4. 對應驗證與證據：例如：v1.01-C5.2.2（檢索套用使用者授權）→ 用另一位客戶的帳號嘗試檢索他人帳單，留測試記錄；v1.01-C9.5.3 → 架構圖標出授權決策點在後端，並留審查紀錄。具體測法轉去 AI Testing Guide。
  5. 這個情境的提醒：報告要寫版本（1.01）、層級、範圍排除項、每條需求的結果與證據。新人若只附一份掃描工具報告，依官方立場是不足的。

4.5 情境範例 B：供應商說「符合 LLMSVS 認證」

情境 B（虛構）：星橋科技的採購

虛構 星橋科技（虛構）要採購一套 LLM 客服平台。供應商的簡報首頁寫著「LLMSVS 認證 · OWASP 認可」，並附一枚像官方徽章的圖示。採購同事想直接把這一項當成安全要求已滿足。

  1. 查官方立場：LLMSVS 2.0 明說 OWASP 目前不認證任何廠商、驗證者或軟體，任何這類標章都不是 OWASP 審核或註冊的。所以「OWASP 認可」這個說法無法成立。
  2. 釐清宣稱的真實內容：供應商或許真的依 LLMSVS 做過自我評估或請第三方評估——官方不禁止提供這類服務，只要不聲稱是 OWASP 官方認證。要問：用的是哪個版本（v2.0？草稿 v2.1？）、目標層級、範圍排除項、評估者是誰。
  3. 要求證據：依官方認證指引，要求評估報告（驗證範圍、通過與未通過、處理失敗的指引）與工作底稿（截圖、重現腳本、proxy 日誌等）；只有掃描工具輸出或問卷，不構成通過。
  4. 決定如何採信：把供應商的報告當作一項輸入，仍要依自身風險決定要不要自己抽驗；可參考紅隊供應商評估準則（見兄弟主題 GenAI 紅隊演練）。
  5. 這個情境的提醒：「有標章」不等於「通過」，要看版本、層級、範圍與證據。

本章重點與自我檢核

  • 先盤點功能、再依風險輪廓選層級、再選標準；層級要在測試前決定。
  • 每條需求要拆成「結果、方法、證據」；方法在 AI Testing Guide，標準只定義查什麼。
  • 證據不能只靠自動化工具或問卷；報告要寫版本、層級、範圍與排除項。
  • OWASP 不認證廠商、驗證者或軟體；任何「LLMSVS 認證」宣稱要追問版本、範圍、評估者與證據。
  • LLMSVS 與 AISVS 的關係官方未說明，任何比較都屬作者整理。
  • 給我一個系統描述，我能說出它該選哪個層級與哪份標準，並寫出理由。
  • 我能把一條需求拆成驗證方法與可留下的證據。
  • 遇到「OWASP 認證」宣稱，我知道該問哪些問題。
  • 我能分清哪些對應是官方明載、哪些是作者整理。
