第 4 章　評估紅隊廠商與工具

  • 預估閱讀：約 9 分鐘（不含章末檢核；另有 4 題章末檢核）
  • 對應學習目標：LO4（含 LO1 的跨文件對應）
  • 前置：第 3 章（測試判準、可重現性、ASR 與預算）

前三章假設你自己做紅隊。但很多組織會採購：請顧問，或買自動化測試工具。問題是，市面上不少服務只是把公開的越獄提示詞跑一遍。Vendor Evaluation Criteria 就是給決策者用的「怎麼分辨」指南。它的讀者是採購者，所以本章讀起來像採購檢核表，每一項都對應前面你學過的概念。

4.1 先分清楚你的系統屬於哪一類

文件把被測系統分成兩類，且每個評估類別都對兩類各給一套期望：

  • 簡單 GenAI 系統：客服聊天機器人、內部 LLM 副駕駛、工作流程助理、FAQ 機器人、RAG 與檢索式問答。典型風險：越獄、有害內容、幻覺、洩漏、內部資料誤用、行為不一致、角色操控。
  • 進階 GenAI 系統：原生工具呼叫、經由 MCP 暴露工具、多代理編排與協作（含 A2A 協定）、自主或角色式 agent、串接下游動作的工作流、持久記憶、與營運自動化整合。典型風險：不安全的工具執行、工具遮蔽、能力升級、agent 間污染、訊息傳遞弱點、記憶與上下文污染、資料外洩。

文件還把廠商分成三種：專做聊天機器人／基本 LLM 的紅隊專家（偏模型與應用層互動）、AI 紅隊顧問（人類對手，擅長複雜多步驟發現、威脅建模與突發行為分析）、自動化 AI 紅隊工具（規模化跑大批測試，常接 CI/CD 做 24/7 持續測試）。文件不處理用 AI 做傳統基礎設施、網路或社交工程紅隊的廠商。

每個類別官方都附紅旗（值得細查的警訊）與綠旗（可能有價值的訊號）。Executive Summary 的快速版已經夠用於初篩：

  • 綠旗：可重現的單輪與多輪對抗評估；不是回收公開越獄庫的客製測試與新發現；清楚且對應業務衝擊的報告；簡單與進階系統都有經驗；關鍵發現有人工驗證；能評估有狀態系統（記憶、長工作階段、跨工作階段行為）；發現能轉成可行動的修補建議。
  • 紅旗：把庫存越獄庫當紅隊；說不清 RAG、記憶、MCP 等架構如何運作；沒有多輪或有狀態測試能力；AI 產生的評估完全沒有人監督；宣稱「完整涵蓋」或「一鍵紅隊」；只看模型輸出、無視動作與系統狀態變化；黑箱評分、不透明的方法。

這張表的讀法（作者整理，非官方）：兩者不是二選一。工具適合你已經知道要測什麼、需要反覆回歸的部分；顧問適合你還不知道失守點在哪、系統越複雜越需要。文件沒有叫你兩者並用，這是依表中「優勢」欄做的推論。文件另列九個常見陷阱：假設簡單系統是安全的；把越獄與系統性紅隊混為一談（例如系統能抗越獄、卻擋不住 Denial of Wallet）；過度重視漂亮的示範，應要求日誌、軌跡與可重現性；把現代架構當聊天機器人；以為自動化能取代有經驗的對手；信任不計入突發行為的指標；沒驗證就假設可重現；假設工具呼叫與 MCP 輸出本身是安全的；過度看重「我們會為你客製建造」這類說法。

4.4 怎麼用：評估流程與探索問題

文件第 5 節提供了「探索問題」，用來穿透行銷說法，分成通用、簡單系統、工具呼叫、MCP 與多代理五組。通用問題包括：給我看新發現，而不只是越獄；你怎麼確保多輪測試可重現；有多少比例的測試是為我們的用例客製的；你怎麼把發現對應到業務風險；怎麼處理非確定性輸出。第 7 節還提供一張評分檢核表，把顧問與工具各自的要求逐類並列。

4.5 情境範例 B：只看越獄分數的採購

情境 B（虛構）：赤松銀行的紅隊工具採購

虛構 赤松銀行是虛構的公司。它的內部理財副駕駛能查詢客戶帳務、起草轉帳申請，並經由 MCP 連到內部工具。採購小組比較兩家廠商：甲只給一份簡報，標題是「我們的工具越獄成功率 97%，涵蓋全部已知攻擊」；乙交來樣本報告，含逐步攻擊鏈、工具呼叫軌跡、嚴重度與業務影響的對應，並說明哪些情境無法自動化測試。採購主管傾向選甲，因為「數字漂亮」。

  1. 甲的主張：「越獄成功率 97%」只衡量模型輸出被誘導的程度，沒有說明是否測了工具呼叫與系統狀態變化。文件把「只看模型輸出，無視動作與系統狀態變化」列為紅旗，且指出越獄只是風險的一小部分（4.2、4.3 節）。
  2. 「涵蓋全部已知攻擊」：文件把宣稱「完整涵蓋」列為紅旗，並在顧問與工具的比較矩陣裡，把「覆蓋幻覺」列為自動化工具的弱點；對 MCP 與多代理系統，自動化工具的適配評級分別只有 Medium-High 與 Low-Medium（表 4-2）。
  3. 乙的證據：逐步攻擊鏈與工具呼叫軌跡對應「透明與可解釋」「可重現」；嚴重度對應業務影響對應「評估嚴謹度」；主動說明限制對應「已知限制」。這些是綠旗。
  4. 該怎麼做：用 4.4 節的探索問題請甲補證據（新發現、可重現的多輪測試、軌跡、資料治理）；補不出來就淘汰。系統屬進階類，應優先考慮顧問，必要時搭配工具做回歸。這個建議是依文件條件做的 作者整理，非官方 判斷。

本章重點與自我檢核

  • 先分系統類型：簡單（聊天、RAG）或進階（工具、MCP、多代理）。每個評估類別對兩類有不同期望。
  • 十三個評估類別，每類有綠旗與紅旗；初篩看：新發現、可重現的多輪測試、軌跡、人工驗證、對應業務風險。
  • 顧問與工具各有優勢：顧問擅長創意與突發行為；工具擅長規模與回歸；多代理系統工具評級只有 Low-Medium。
  • 「只會越獄」「完整涵蓋」「一鍵紅隊」「黑箱評分」都是紅旗。
  • Manual 與 AISVS（C9 防禦對應）、AIVSS（評分分開記）、AI Testing Guide（README 列出 Red Teaming Guide）有官方連結。
  • 我能說出簡單與進階 GenAI 系統各舉兩個例子。
  • 我能舉出至少三個紅旗，並說明為什麼是紅旗。
  • 我能判斷一個多代理系統該優先找顧問還是工具，並說明依據。
