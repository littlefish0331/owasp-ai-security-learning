  • 前置：資安前置觀念：風險（威脅、漏洞、風險的區別）；知道 CVSS 是什麼更好，不知道也可以，本章會用一段話交代

這個主題在 06「評估與驗證」裡負責回答一個很實際的問題：找到一個 AI 系統的弱點之後，怎麼說它有多嚴重？紅隊找到問題、測試指南跑出問題、驗證標準列出沒達標的要求，最後都要排優先順序。AIVSS (AI Vulnerability Scoring System) 是 OWASP 為此做的評分專案。但它有一個你必須先知道的麻煩：目前同時有三套彼此不相容的說法。本章先講為什麼需要它，再把三套說法分開。

1.1 核心概念：為什麼 CVSS 不夠，以及放大原則

先用一段話交代 CVSS：通用弱點評分系統 (Common Vulnerability Scoring System, CVSS) 是軟體弱點最常用的評分方式，用攻擊途徑、複雜度、所需權限、對機密性／完整性／可用性的影響等指標算出 0 到 10 的分數，再分成低、中、高、嚴重四個級別。開發者最熟悉的場景是：套件掃描器報一個 CVE，旁邊附一個 CVSS 分數，你依分數決定先修哪個。

AIVSS 的核心想法：agent 能力是「放大器」

是什麼
AIVSS 想補的缺口是：同一個技術弱點，部署在不同的 AI 系統裡，真正的危害可以差很多。v0.8 規格把這件事稱為「風險放大」(Agentic Risk Amplification)：傳統軟體的弱點，影響上限由應用程式本身的權限決定；agentic AI 的規劃、用工具與保留記憶的能力，則像「力量倍增器」(Force Multiplier)，把原本的技術弱點放大。官方
為什麼會發生
v0.8 列出三個原因：(1) 核心自主性 (Core Agency)：agent 能自己把幾個弱點串成達成目標的路徑；(2) 環境滲透性 (Environmental Permeability)：agent 把自然語言指令和系統執行（工具）接在一起，讓技術缺陷跨越系統邊界；(3) 機率性行為 (Probabilistic Behavior)：弱點可能只在特定隨機條件下觸發，評估要從「可利用性」轉向「機率」。官方通用框架的 README 另外列出傳統評分的盲點：對抗式輸入、不透明且難預測的推理、模型隨時間退化、涵蓋資料到維運的生命週期弱點、倫理與社會影響，以及系統本身的動態性。官方
怎麼被忽略（概念層級）
以 README 自己的例子說：客服聊天機器人被提示詞注入，洩漏內部指示。系統「照設計在運作」，卻產出不安全的結果，而傳統評分偏重軟體缺陷與可觀察的失效，容易低估這類行為性的風險。官方換成開發者的語言：SQL 注入的後果受資料庫帳號權限限制；一個能自己呼叫工具、跨工作階段記憶的 agent，被注入後的後果則取決於它「被授權做什麼」。作者整理，非官方
怎麼用
評分時把「技術嚴重度」當基線，再問 agent 的能力（自主性、工具、持久記憶、身分切換等）讓它往上加多少。這個「加多少」是 AIVSS 與 CVSS 的差別所在，也是第 2 章算式的結構。
常見誤解
「AIVSS 是 CVSS 的替代品。」不是。v0.8 規格要求先有 CVSS v4.0 基礎分，再加 agentic 的放大項；1.0 參考計算器更是明白寫成 CVSS v4.0 的擴充，原本的 CVSS 向量與分數保持不變。（細節見第 2、3 章。）

1.3 遇到分數時，該讀哪一份？

1.4 一個值得知道的觀察：README 的範例分數很低

README 附了一段示範程式，註解寫最終分數約 0.323，屬「Low」，並說明這是「簡化、示意」的例子。官方本教材另外做了兩個觀察，都是作者自己的，不是官方說法：(1) 九個 0 到 1 之間的指標連乘，數值會迅速變小（九個都取 0.9 連乘約為 0.39，九個都取 0.7 約為 0.04），所以這種算法天然會把分數壓低；(2) 本教材用 README 給的算式與數值重算，得到的結果與它的註解數字不同（重算約 0.23，註解寫 0.323；中間的 AI 特有指標得分也不同）。這可能是示意程式的簡化或筆誤，本教材無法確認原因。作者整理，非官方（作者計算）

這個觀察對學習的意義是：不要拿甲套的範例去校準你對嚴重度的直覺。它的作用是說明框架的組成，而不是示範一個可信的嚴重度分數。

本章重點與自我檢核

  • AIVSS 的出發點是放大原則：agent 的自主性、工具、記憶等能力會把同一個技術弱點「放大」，CVSS 看不到這一層。
  • 目前並存三套說法：甲（儲存庫 README 通用框架）、乙（版本 v0.8 的規格）、丙（1.0 參考計算器）；它們的算法與輸入不同，不能混用。
  • 現行有效的是哪一套，官方沒有說明，未能確認；記錄分數時要連版本一起記，例如註明分數出自 v0.8 還是出自 1.0 計算器。
  • README 範例分數很低，不適合用來建立嚴重度直覺。
  • 我能用兩三句話說明為什麼同一個技術弱點在 agent 身上可能更嚴重。
  • 我能說出三套 AIVSS 說法各自的來源，並知道為什麼不能把它們的分數比較。
