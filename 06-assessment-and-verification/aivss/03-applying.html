3.1 情境 A：同一個弱點，兩種部署

情境 A（虛構）：杉林網路的客服系統

虛構 杉林網路是虛構的公司。資安團隊發現客服 LLM 存在間接提示詞注入弱點：攻擊者可以把指令藏在客戶上傳的文件裡。底層弱點相同，他們用 CVSS v4.0 評出基礎分 6.0（Medium）。但公司有兩種部署，要各自評分。作者整理，非官方（基礎分 6.0 是作者為了教學假設的）

  1. 部署一：唯讀問答助理。只能讀知識庫、人工審核每個動作，沒有跨工作階段記憶。因子評分：Language 0.5、Context 0.5、Non-Determinism 0.5、Opacity 0.5，其餘 0。Factor_Sum ＝ 2.0。代入算式（ThM 0.97、緩解係數 1.0）：AARS ＝ (10 − 6.0) × 0.2 × 0.97 ≈ 0.78；AIVSS ＝ 6.0 + 0.78 ≈ 6.8（Medium）。
  2. 部署二：可寫入正式環境的 agent。同一個 LLM 與弱點，但這個 agent 能自主在正式系統提交動作、用高權限工具、有長期記憶。因子評分：Autonomy 1.0、Tools 1.0、Language 1.0、Context 0.5、Non-Determinism 1.0、Opacity 0.5、Persistence 1.0、Identity 0.5，其餘 0。Factor_Sum ＝ 6.5。AARS ＝ 4.0 × 0.65 × 0.97 ≈ 2.52；AIVSS ＝ 6.0 + 2.52 ≈ 8.5（High）。
  3. 比較。兩者的 CVSS 基礎分完全相同，AIVSS 級別卻從 Medium 變成 High。差別完全來自部署脈絡。這就是第 1 章「放大原則」的具體樣子。
  4. 補救該做什麼？作者另外算了兩種補救（同樣是作者計算）。只修底層弱點，把基礎分從 6.0 降到 3.0、agent 因子不變：AIVSS ≈ 7.4，仍是 High。若改為限縮部署（取消自主提交，Autonomy 改 0；工具改為受限允許清單，Tools 0.5；記憶改為工作階段內，Persistence 0.5），基礎分仍是 6.0：Factor_Sum 變 4.5，AIVSS ≈ 7.7，仍是 High，但下降 0.8；若部署不變、只補上經驗證的部分緩解（係數 0.83），原本的 8.5 會降到約 7.1。
  5. 這個情境的提醒：v0.8 規格自己也說，當放大量遠大於基礎分時，主要風險來源是部署脈絡，補救重點應是限縮 agent（降低自主性、限縮工具、縮短記憶保留、增加人工監督），只修底層弱點不會明顯降低風險。官方

作者計算，非官方範例：以上數字用 Python 以規格公式計算，輸入已完整列出；因子評分是作者為了教學做的主觀選擇，不是官方範例。規格自己的範例用不同的弱點與評分，細節請看 PDF 的 3.6 節。

3.2 情境 B：把分數平均成儀表板

情境 B（虛構）：星橋金融的月報

虛構 星橋金融是虛構的公司。安全主管要求把本月所有 AIVSS 分數平均，做成一個「AI 風險指數」放在儀表板上，並用小數位排序修補順序。本月六個發現：9.7、9.4、3.5、3.2、2.8、2.5。

  1. 平均的結果。六個分數的平均是 5.18，四捨五入為 5.2，落在 Medium。作者計算，非官方範例
  2. 問題在哪裡？原始六個發現中有兩個 Critical、四個 Low，沒有任何一個是 Medium。平均把兩個最需要立刻處理的問題，稀釋成一個看起來「還好」的 Medium。規格明說：分數是順序尺度，不要跨發現平均，因為平均順序值沒有意義；分析單位是單一發現與其嚴重度級別。官方
  3. 小數位排序的問題。9.7 與 9.4 同屬 Critical，視為等價；用 0.3 的差距決定先後，是在「解讀雜訊」。更合理的排序是：先依級別，同級內再看其他風險資訊（可被利用性、影響範圍、補救成本）。作者整理，非官方
  4. 比較好的儀表板。顯示各級別的數量與未結案件（例如 Critical 2、High 0、Medium 0、Low 4），並標註每個分數所用的 AIVSS 版本；不提供單一指數。作者整理，非官方

3.3 更新的方向：1.0 的查表模型

丙：AIVSS 1.0 參考計算器把做法改了。它是 CVSS v4.0 的擴充：保留原本的 CVSS-BTE 分數與向量不動，另外用一組五個「類別式」的 Agentic 指標描述弱點所在的利用路徑，再查表得到 AIVSS。不對 agentic 指標做任何算術。（資料來自計算器頁面、候選儲存庫的 README 與其參考計算器原始碼。）

表 3-1　AIVSS 1.0 的五個 Agentic 指標，合稱 Agentic AI Profile
指標全名問的是什麼（用作者自己的話）值
LCLanguage-Mediated Control攻擊者控制的自然語言多直接地影響安全相關的決策或工具呼叫D 直接、I 間接（藉由檢索或匯入的內容）、M 受獨立強制的結構化轉換中介、N 無、X 證據不足
CPContext Persistence攻擊者控制的脈絡或記憶能存活多久，是否超出原工作階段C 跨工作階段記憶、S 僅工作階段、N 無、X 證據不足
APAgentic Control Propagation被入侵的意圖或權限是否跨過信任邊界到另一個 agent、租戶、主體或政策領域L 橫向（跨邊界）、C 受限（同主體同政策領域內）、N 無、X 證據不足

ESExtension Binding Surface路徑上可達的工具、技能、MCP server、外掛綁定得多緊；只影響資訊性的「Agentic Uplift U」，不影響分數W 寬、M 受管、N 無或窄、X 證據不足

LC、CP、AP、RH 四個指標依一組有順序的規則決定 Agentic Effect Class（A0 無、A1 存在、A2 顯著、AX 證據不足），先符合先用。依參考計算器的原始碼，規則大致是：AP 為 L，或 LC 為 D／I 且 CP 為 C，或 LC 為 D／I 且 RH 為 D，歸 A2；LC 為 D／I，或 CP 為 S／C，或 AP 為 C，或 RH 為 D，歸 A1；其餘若有 X 歸 AX，否則 A0。（以原始碼為準，細節請看規格 5.6 節；本教材沒有讀到完整規格文字。）作者整理，非官方

規則：A0 與 AX 維持 CVSS-BTE 不變（AX 的結果標為暫定 provisional）；A1 與 A2 取「表格值」與 CVSS-BTE 的較大者，所以 AIVSS 永不低於 CVSS-BTE。任何分類指標（LC、CP、AP、RH）為 X，代表證據不足，結果被標為暫定，而不是預設為無風險。所以「還沒測就先填 N」是錯的：N 的意思是已確認沒有，沒看到證據應該填 X。官方（X 的定義）；對填寫習慣的提醒為作者整理，非官方

作者計算，非官方範例：沿用情境 A 的基礎分 6.0（Medium）。唯讀問答助理若 LC＝I、其餘 N，歸 A1，AIVSS ＝ 7.5；可寫入正式環境的 agent 若 LC＝I、CP＝C，歸 A2，AIVSS ＝ 8.9。注意：同一個弱點，用 v0.8 算是 6.8 與 8.5，用 1.0 查表是 7.5 與 8.9。這正是第 1 章說「不同版本的分數不能比較」的原因：即使兩份報告剛好寫出 7.7 與 7.5 這樣相近的數字，也可能一份來自 v0.8 的十因子算式、另一份來自 1.0 的查表，輸入與意義都不同。

1.0 的自我聲明：請當作草案看待

計算器頁面與候選儲存庫自己寫明：Table 6 的格值是尚未對獨立評分的發現驗證的政策設定；Effect Class 未經驗證；補救時間線（SSVC／BOD 26-04）是「實驗性、未校準」；FIRST 沒有驗證或背書；範例是合成的測試資料，不是真實事件；並明寫「OWASP does not endorse AIVSS v1」。程式碼授權是 Apache-2.0。因此本教材不把 1.0 說成現行標準，只把它當作「官方網站目前展示的方向」來教。

本章重點與自我檢核

  • 同一個技術弱點，因部署脈絡不同，AIVSS 級別可以不同；只修底層弱點不一定降級，限縮 agent 的自主性、工具與記憶往往更有效。
  • 不要平均 AIVSS 分數，也不要用小數位排名；儀表板用各級別的數量與未結案件。
  • 1.0 是查表模型：五個類別式指標 → Effect Class → Table 6；AIVSS 永不低於 CVSS-BTE；X 代表證據不足，結果暫定。
  • 1.0 自述未驗證、OWASP 不背書；三套版本的分數不能比較。
  • AIVSS 是評分，不是測試，也不是驗證標準；它與紅隊、測試、驗證標準組合使用。
  • 給我兩個部署脈絡不同的相同弱點，我能解釋為什麼 AIVSS 級別可以不同。
  • 我能指出「把分數平均成指數」的問題，並提出替代的呈現方式。
  • 我能說出 1.0 五個指標中至少四個的意思，與 AIVSS 為什麼「永不低於 CVSS-BTE」。
  • 我知道為什麼本教材不宣稱 1.0 是現行標準。
