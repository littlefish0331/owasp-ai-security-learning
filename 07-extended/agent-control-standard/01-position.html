如果你用過 CI 的合併閘門 (gate) 或 API Gateway，ACS 的直覺並不陌生：不要讓一個有能力做很多事的程式，自己決定自己能不能做。差別在於 ACS 把這個「閘門」搬到 Agent 的每個關鍵動作之前，並想讓它成為跨框架的開放標準。這一章回答：它到底是什麼、成熟到哪裡，以及引用它時要避開哪些說法。

1.2 三個版本，三個意思

你可能會看到「ACS 0.1.0」「ACS 0.1.4」「ACS 2026-09-01」三種寫法，它們說的是不同的東西：

表 1-2　ACS 的三種版本／日期標示
標示指的是出處
v0.1.0規格版本（線路協定與語意）；JSON Schema 的網址也含 v0.1.0README、規格文字
0.1.4儲存庫發行版本（規格、文件與參考實作的整體修訂）version.txt、CHANGELOG
2026-09-01在 genai.owasp.org 資源頁上登錄的日期；資源頁沒有標版本與成熟度資源頁

規格版本沒變，內容卻就地改變

CHANGELOG 在 0.1.4 寫明：這次對 ACS-Trace 做了破壞性變更（例如每個步驟的 span 現在必須帶 acs.request_id 與 acs.session.id），但「規格版本維持 v0.1.0，所以 /schema/v0.1.0/ 網址下的檔案是就地更改的，握手無法分辨新舊規則」。換句話說，兩個宣稱「符合 ACS v0.1.0」的實作，可能依據的是不同時間點的規則。官方的建議是：宣稱 Trace 符合性時，要指名發行版本或提交。這正是早期規格的樣子。

1.3 「自行宣告，無人驗證」

ACS 的符合性是這樣運作的：一個部署在握手時宣告自己支援哪些設定檔 (profile)，對方回報接受哪些。規格自己寫得很直白：

  • 這些宣告是自我宣告，不是被驗證的事實。conformance 文件明說：「v0.1.0 中，誰來驗證符合性宣告？沒有人。」這個版本沒有符合性測試套件、沒有符合實作的登記冊，也沒有負責仲裁爭議的管理單位。
  • 參考實作也不主張自己通過任何驗證。README 說它的主張範圍很窄：一個 Guardian、兩個 Agent 客戶端、一份線路契約，以及一份已發布的矩陣，說明 ACS v0.1.0 對 Microsoft Agent Governance Toolkit 能表達與不能表達的部分。它明說這不是「對 Microsoft AGT 做過整份規格互通性測試」的主張。

這意味著：聽到「我們的產品符合 ACS」，在 v0.1.0 這個階段，它的意思是「我們宣告符合」，而不是「有人驗證過」。你可以把它當成一個設計方向與對話的共同語言，但不要把它當成一個認證。

1.4 核心概念：把「做」與「准不准做」分開

職責分離的 Agent 版

是什麼
ACS 的核心想法是職責分離：Agent 想做的事，由另一個獨立的角色 (Guardian) 在事前審查。規格的設計原則之一是「Agent 不得知道有鉤子存在」，政策判斷也不經過 Agent 自己的輸出路徑。
為什麼會發生（為什麼需要）
你在技能主題與 AI Exchange 都看過同一個問題：Agent 可能被提示詞注入、載入惡意技能，或單純出錯，而且它用的是自己的完整權限。如果「要不要做」由 Agent 自己決定，一旦它被帶偏，判斷也跟著被帶偏。
怎麼運作（概念層級）
Agent 在關鍵動作前（例如要呼叫某個工具）先送出一個結構化的請求給 Guardian；Guardian 依政策回答；Agent 必須等答案並照做。第 2 章會細講。
怎麼防（它提供的控制）
它在 AI Exchange 的語言裡，接近限制後果與偵測／回應的控制：事前攔截（預防）加上稽核軌跡（偵測與事後重建）。這個對應是作者整理，非官方；官方沒有把 ACS 放進 AI Exchange 的分類。
常見誤解
「有了 Guardian，Agent 就安全了。」Guardian 本身是新的信任點：它必須可用、被認證、政策寫得對。規格自己就承認：Guardian 不可達時預設放行，而參考實作甚至還沒做到線路認證。ACS 增加一道閘門，不是消除風險。

1.5 與相鄰文件的關係

  • 與技能：ACS 有三個專門的鉤子（skillRegister、skillLoad、skillUnload），覆蓋技能進入、啟用與離開的生命週期。這是Agentic Skills Top 10 談的技能層，可以在這裡被攔截。
  • 與 MCP：規格有「包裝後的 MCP」(protocols/MCP/*) 命名空間，用於會涉及 MCP 的工作階段。
  • 與 AIBOM：ACS 的 Inspect 支柱產出 AgBOM（Agent 物料清單），可序列化為 CycloneDX、SPDX 或 SWID。這與本階段的 AIBOM 主題相鄰，但 AgBOM 與 AIBOM Generator 是否為同一件事，官方頁面沒有說明，教材不下結論。
  • 與 Agent Observability Standard (AOS)：owasp.org 的 GitHub 組織另有 AOS，用語與 ACS 相近（可檢視、可追蹤）。官方頁面沒有說明兩者的關係，未能確認。

本章重點與自我檢核

  • ACS 是開放標準：獨立的 Guardian 在 Agent 動手前審查並決定；規格 v0.1.0，儲存庫 0.1.4，資源頁登錄日 2026-09-01，三者意思不同。
  • 符合性是自行宣告：v0.1.0 沒有驗證者、沒有測試套件、沒有登記冊。
  • 規格版本沒變，ACS-Trace 的內容在 0.1.4 就地做了破壞性變更；宣稱符合時要指名發行版本。
  • 授權依檔案分：規格與程式碼 Apache-2.0；說明文件 CC BY-SA 4.0。
  • Guardian 不是銀彈：它本身是新的信任點。
  • 我能區分 v0.1.0、0.1.4 與 2026-09-01 各指什麼。
  • 我能說明「符合 ACS」在 v0.1.0 的實際意思。
  • 我能說出 ACS 與技能、MCP、AgBOM 的關係，以及哪些關係官方沒有說明。
