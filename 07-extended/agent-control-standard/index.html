Agent Control Standard

  • 採用來源：genai.owasp.org 資源頁、GitHub 儲存庫 GenAI-Security-Project/agent-control-standard（README、規格文字、CHANGELOG、LICENSING、GOVERNANCE），2026-10-26 讀取

前面的主題大多在談「Agent 可能出什麼事」。Agent Control Standard (ACS) 談的是另一件事：在 Agent 動手之前，讓另一個獨立的角色先看一眼、決定放不放行。這個主題帶你讀 ACS 的核心設計（Guardian 與 Observed Agent、鉤子 (hook)、五種處置），並特別留意兩件事：它的失敗姿態預設是「放行」，以及它自己承認「沒有人驗證符合性宣告」。學完後，你能說出 ACS 解決什麼問題、它有哪些關鍵設計取捨，以及為什麼這是一份仍在早期的規格。

學習目標

學完這個主題，你應該能：

  1. 定位與成熟度：說明 ACS 是什麼、解決什麼問題、現行版本與成熟度（規格 v0.1.0、倉庫 0.1.4），以及「自行宣告、無人驗證」的限制。
    對應：第 1 章
  2. 核心設計：說明 Guardian 與 Observed Agent 的分工、鉤子的概念、五種處置，以及三支柱與符合性設定檔 (profile) 的關係。
    對應：第 2 章
  3. 失敗姿態與取捨：解釋 fail-open 與 fail-closed 的差別、ACS 的預設值與理由，並判斷一個部署該怎麼設定。
    對應：第 3 章

本主題三個重點

  • ACS 把「Agent 要做什麼」與「這件事該不該做」拆成兩個角色：被觀察的 Agent 在每個鉤子點先問，獨立的 Guardian 回答允許、拒絕、修改、詢問或延後。
  • 它的預設失敗姿態是失效即放行 (Fail-open)：Guardian 掛了、逾時或不可達時，Agent 照常繼續（但必須留下稽核紀錄）。規格明說這是用強制力換可用性，可以改成拒絕。
  • 它是早期規格：規格 v0.1.0、倉庫 0.1.4；符合性是自行宣告，v0.1.0 沒有人驗證；參考實作自己列出缺口（線路未認證）。
