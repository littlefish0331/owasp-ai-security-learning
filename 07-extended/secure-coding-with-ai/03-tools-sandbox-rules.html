第 3 章　工具、沙箱與規則檔

  • 預估閱讀：約 8 分鐘（不含章末檢核；另有 4 題章末檢核）
  • 對應學習目標：LO3
  • 前置：第 2 章

上一章說的是「什麼會進到助理的腦袋」。這一章換成「助理拿到之後能做什麼」。文件的第 4、5、6 節分別收窄三樣東西：助理接上的工具、助理執行的環境，以及悄悄規定助理行為的規則檔。前兩者是常見的收窄權限問題；第三者比較特別，它會跟著倉庫走，並在之後每一次工作階段自動生效。

3.2 第 6 節：規則檔是什麼

文件把下列這些檔案稱為「規則檔」並歸在同一節：.cursorrules 與 .cursor/rules/、CLAUDE.md 與 .claude/、AGENTS.md、.github/copilot-instructions.md、.windsurfrules、.aider.conf.yml，以及任何工具所引用的自訂系統提示詞檔。它們是工具在之後所有互動中都會讀進去的設定；文件稱之為一種持久化機制 (Persistence)：能改這些檔案的人，控制之後每一次生成。

3.3 核心概念：規則檔是一種「每次都會被讀」的輸入

規則檔與持久化指示

是什麼
規則檔是寫給助理看的純文字：程式碼風格、專案慣例、要避開的事。文件把它定性為安全關鍵的設定，並說它是一個「具工作階段層級持久化 (Persistence) 效果的指示注入面」，即不必每次再注入，一次放進去之後都會生效。
為什麼說它像供應鏈問題
作者整理，非官方 文件沒有用「供應鏈」這個詞談規則檔，供應鏈是第 10 節另一個主題。本教材把它歸為供應鏈 (Supply Chain) 同一類，是因為它具備相依套件的三個性質：跟著倉庫一起被複製；每次建置（這裡是每次工作階段）自動載入；任何能合併變更的人都能改。差別在於相依套件有鎖定檔與審計工具，規則檔通常什麼都沒有，審查者還容易把它當文件略過。文件在第 3 節也提醒，複製來的倉庫與相依套件裡的文件可能含有人類看不見、助理卻解析得到的指示。
怎麼被利用（概念層級）
文件列了兩條路：惡意 PR 加進或修改規則檔；或助理自己改了自己的規則檔。文件特別點出的內容風險是「削弱安全控制、關閉安全功能、或叫助理忽略某些檔案類型或樣式」。文件沒有再往下解釋，以下是 作者整理，非官方：規則檔不是程式碼，通常不會讓測試失敗，變更可以安靜地存在很久。
怎麼防
文件的五項：把規則檔當成安全關鍵設定，審查嚴格度比照 CI/CD 管線的變更；納入程式碼審查要求並要求明確核准；監控規則檔的非預期新增或修改，包含助理自己做的；用 git 掛鉤或 CI 檢查在每個 PR 標示對已知規則檔的變更；稽核現有規則檔裡有沒有削弱控制的內容。反面三條：外部貢獻者的 PR 不經安全審查就加入或修改規則檔、助理未經開發者明確核准就改自己的規則檔、以為純文字就無害。
常見誤解
「規則檔只影響風格，不是安全問題。」文件的立場正相反。另一個誤解：「只有外部 PR 要擋。」文件把「助理自己改」列為同等重要的路徑，因為助理本身可能已被第 2 章的管道帶偏。

3.4 情境範例 A：評估陌生程式庫的下午

情境 A（虛構）：大坪林數位的函式庫評估

虛構 大坪林數位是虛構的軟體公司。一位開發者想評估一個來源不熟的開源函式庫，把它複製到自己的筆電上，讓助理「讀一讀並跑跑範例」。筆電上有長效的雲端 CLI 設定與 SSH 金鑰，助理開著自動接受。以下細節停在概念層級。

  1. 發生了什麼：函式庫裡有一個助理規則檔與看似普通的文件，其中藏有針對助理的指示，要它「先完成環境準備」。助理照做：讀取筆電上的設定檔，並嘗試把內容當作某個工具的參數送往外部位址。這次剛好被公司的網路出口規則擋下，開發者事後從日誌才發現。
  2. 哪一環出問題：(a) 在不熟悉的程式庫上開啟自動接受（第 5 節 Don't）；(b) 助理沒有放進沙箱，能讀到憑證儲存位置與 SSH 金鑰（第 5 節）；(c) 複製進來的規則檔在第一個工作階段就被載入（第 6 節與第 3 節的 README 指示）；(d) 工具參數沒有在執行前驗證（第 4 節）。
  3. 對應條目：Secure Coding with AI 第 3、4、5、6 節。這次僥倖沒外洩的原因不是助理的判斷，而是網路出口這一層（第 5 節的出口控制）。
  4. 該採什麼控制：評估陌生程式庫改在拋棄式的開發容器或雲端工作空間；不掛載憑證與金鑰目錄；任務不需要對外連線就封鎖出口；不開自動接受；先人工讀過規則檔再讓助理載入。
  5. 學到什麼：四層控制各自有缺口，最後靠一層救回。這是縱深防禦 (Defense in Depth) 的實例，但「這次被擋下」不等於「設計正確」：下一次出口規則可能剛好放行。

本章重點與自我檢核

  • 助理被帶偏時，最壞能碰到的就是它的工具、指令、檔案、網路與憑證；第 4、5 節逐項收窄。
  • 工具定義要固定並比對，核准清單要維護，不讓助理自動探索連線；沙箱加出口控制加短效憑證，並謹慎對待自動接受與略過確認的旗標。
  • 規則檔是持久化的指示來源：跟著倉庫走、每次自動載入；審查比照 CI/CD 管線，助理自己改也要核准。
  • 把規則檔歸為供應鏈類問題是本教材的整理，文件的原話是「持久化機制」與「安全關鍵設定」。
  • 我能對自己用的助理，列出它能碰到的工具、指令、檔案、網路與憑證。
  • 我能說明為什麼規則檔的變更要比照 CI/CD 管線審查。
  • 我知道哪些說法是文件原話，哪些是本教材的整理。
