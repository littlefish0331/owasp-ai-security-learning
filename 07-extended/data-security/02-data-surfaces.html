第 2 章　GenAI 的資料面與 AI-DSPM

  • 預估閱讀：約 8 分鐘（不含章末檢核；另有 4 題章末檢核）
  • 對應學習目標：LO2
  • 前置：第 1 章

在傳統系統裡，「保護資料」大致是保護資料庫、檔案和傳輸通道。GenAI 讓這件事複雜了：同一筆資料可能同時存在於原始文件、嵌入、快取、日誌，甚至模型權重。這一章先回答兩個問題：要保護的資料到底有哪幾類？以及為什麼上下文視窗是 GenAI 資料安全最特別的地方？最後介紹官方用來做「資料盤點與持續管理」的 AI-DSPM。

2.1 要保護的六類資料

2026 版對 GenAI 脈絡下的資料安全下的定義，是保護資料的機密性、完整性、可用性與真實性 (authenticity)，涵蓋訓練與微調、檢索 (RAG)、工具使用、Agent 記憶、遙測與可觀測性、推論時處理和下游輸出。它把要保護的資料分成六類：

類別官方列舉的例子為什麼容易漏掉（作者整理，非官方）
來源資料
(Source data)		原始語料（結構化與非結構化）、使用者上傳、工單、知識庫、分析匯出最直覺，通常已有保護
衍生資料
(Derived data)		嵌入、索引、檢索出的段落、摘要、合成資料集、特徵庫來源刪了它還在；常沒有繼承來源的分類標籤
模型產物
(Model artifacts)		檢查點、adapter／LoRA、訓練日誌、評估集、模型登錄庫被當成「程式碼」而不是「資料」管理
執行期資料
(Runtime data)		prompts、上下文視窗、工具呼叫（LLM 到 SQL／Graph／API）、Agent 之間的訊息、暫存快取（例如 KV cache）、工作階段記憶存活時間短，被認為「用完即丟」
營運副產物
(Operational exhaust)		日誌、追蹤 (traces)、除錯模式擷取、監控管線建置時只想著除錯方便，沒有當成敏感資料存放處
Agent 狀態與委派產物Agent 記憶（短期與長期）、Agent 間訊息、工具呼叫的酬載與結果、委派鏈、被快取的憑證隨 Agent 架構浮現的新類別，傳統資產清單沒有

這張表最值得記的一點是：後四類資料在傳統資料盤點裡通常不存在。如果你的資產清單只有「資料庫與檔案」，GenAI 系統裡大部分的敏感資料流都在清單之外。

2.2 核心概念：上下文視窗是一個扁平的信任空間

沒有內部存取控制的混合空間

是什麼
官方說，有一個架構特性讓 GenAI 的資料安全和以往所有運算模型根本不同：上下文視窗把多個信任域（system prompt、使用者輸入、RAG 結果、工具輸出、對話歷史）聚合進一個扁平的命名空間，內部沒有存取控制。從機密 HR 資料庫取回的一段 RAG 內容，和使用者的輸入享有相同的信任權重。
為什麼會發生
模型只看到一長串 token，沒有「這一段只能用來推理、不能原文輸出」的標記。官方明說：目前沒有機制可以把上下文的某一段標成「可用於推理但不可直接輸出」，或「可用於決策但不可轉發給其他 Agent」。這也是為什麼控制平面（指令）與資料平面（內容）在這裡融合。
對安全的含意（概念層級）
只要某段敏感內容進了上下文視窗，它在原理上就可能被輸出。所以官方把好幾個條目（DSGAI01、DSGAI19、DSGAI21，以及文中另一個殘留的 DSGAI25 引用）追溯到這個根因，並直言：這些條目的緩解是「繞過」這個限制，而不是「解決」它。
怎麼防（官方的三個姿態）
(1) 最小化與受控上下文：只送需要的，避免過寬的上下文視窗。(2) 隔離與最小權限：每租戶、每使用者、每 Agent 的邊界，工具權限有範圍，高風險或不可逆動作需要人工核准。(3) 生命週期嚴謹：保留與刪除要涵蓋原始與衍生資產（嵌入、備份）。官方的基本態度是「對模型零固有信任（它可能透過記憶、反推或輸出洩漏資料）」。
常見誤解
「我在 system prompt 寫了『不要輸出機密』，所以機密被保護了。」那是請求，不是存取控制。要減少風險，是讓機密內容根本不進入這個上下文，而不是進去後再要求模型保密。

2.3 AI-DSPM：把資料盤點變成持續的工作

資料安全態勢管理 (DSPM) 是傳統資料安全的做法：持續找出資料在哪裡、分類、治理、監控。官方把它延伸到 GenAI，稱為 AI-DSPM：在 GenAI 管線與執行期，持續地探索、分類、治理與監控資料，讓你看得到敏感資料在哪裡、如何衍生（例如進入嵌入或日誌），並執行能防止外洩、竄改與不合規的控制。官方列了 13 個能力類別，下表挑出最能說明「GenAI 不一樣在哪」的幾項：

能力官方要點對應的風險（作者整理，非官方）
資產探索與清單盤點訓練集、評估集、prompt 樣板、system prompt、Agent 記憶、RAG 來源、向量資料庫、嵌入管線、外掛與 MCP 工具、LLM 閘道、快取，以及可能擷取完整 prompt 的日誌。目標是消除「未知的資料儲存」與隱藏的 AI 資料路徑影子 AI、過度暴露
分類與政策綁定把既有分類延伸到 prompts、嵌入、檢索片段、工具酬載與可觀測事件；標籤必須傳遞到衍生物（嵌入、快取、備份），不只是原始檔案衍生物外洩、刪除不完整
資料流、血緣與「GenAI 物料清單」維護來源→預處理→嵌入→索引→檢索→組 prompt→生成→日誌的端到端血緣，以及資料集版本→模型版本→部署版本。加入 DBOM (Data Bill of Materials) 概念，以 CycloneDX ML-BOM (ECMA-424，v1.7) 為基礎格式，記錄來源、攝入時間、預處理步驟、分類標籤與授權投毒與供應鏈、舉證出處
存取治理細粒度 RBAC／ABAC；短效憑證；每個 Agent 有自己的身分與範圍；即時 (JIT) 資料存取：不給 Agent 常駐憑證，而是針對任務發出帶範圍與有效期的暫時 token，完成即撤銷身分與憑證外洩
可觀測性與日誌保留最少日誌的預設值（預設不記完整內容）、對 prompts、工具輸出與機密做代碼化或遮蔽、除錯追蹤短 TTL 並需核准、對可觀測平台本身做存取控制與監控遙測外洩
生命週期、抹除與合規刪除或讓與已刪除來源相關的嵌入、索引、快取與備份過期；支援資料主體權利並可追溯；追蹤合法依據與用途限制；除非需要，預設零保留刪除請求後資料仍留存

一個值得留意的細節：官方的「GenAI 物料清單／DBOM」直接指向 CycloneDX 的 ML-BOM。這是資料安全與AIBOM 主題相連的地方；第 5 章會回來談。

2.4 2025 版怎麼談資料管線

2025 版的 Best Practices 用的是更傳統的資料管線語言。它的「Data」一節把管線分成六個主要階段，另外有兩個附加階段，每個階段都寫了「發生什麼、安全控制、測試」：

  • 主要階段：資料來源 (Data Sources)、資料載入器 (Data Loaders)、資料湖 (Data Lake)、準備與計算 (Preparation/Computation)、資料倉儲 (Data Warehouse)、資料分享 (Data Sharing)。
  • 附加階段：洞察庫 (Insight Stores)，存放衍生的洞察、模型輸出與中繼資料；AI 庫 (AI Store)，存放模型、相關資料集、程式碼與設定，用於可重現與版本管理。

兩份文件的差異可以這樣看（作者整理，非官方）：2025 版是「資料經過哪些階段、每階段做什麼控制」；2026 版是「GenAI 特有的資料風險有哪些、各自分幾層控制」。前者像施工圖，後者像風險登記冊。兩者互補，但 2025 版對齊的是 LLM Top 10 2025。

本章重點與自我檢核

  • 要保護的資料有六類：來源、衍生、模型產物、執行期、營運副產物、Agent 狀態。後四類通常不在傳統資料盤點裡。
  • 上下文視窗把多個信任域聚合進單一扁平空間，內部沒有存取控制；官方承認好幾個條目的緩解是繞過而非解決這個限制。
  • AI-DSPM 把資料盤點變成持續工作；分類標籤要傳遞到衍生物；JIT 資料存取用任務範圍的暫時憑證取代常駐憑證。
  • 2025 版談資料管線階段，2026 版談風險條目與分層控制；兩者互補，且對齊的 LLM Top 10 年份不同。

  • 我能解釋為什麼「在 system prompt 叫模型保密」不是存取控制。
