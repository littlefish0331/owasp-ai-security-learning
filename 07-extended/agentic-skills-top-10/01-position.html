第 1 章　全貌與定位

  • 預估閱讀：約 7 分鐘（不含章末檢核；另有 3 題章末檢核）
  • 對應學習目標：LO1

你已經知道 Agent 會呼叫工具，也聽過 MCP。但現在很多 Agent 還會載入「技能」：一個資料夾，裡面是給模型讀的指令，外加一些腳本與資源。AST10 就是專門談這一層的風險清單。這一章回答三件事：技能到底夾在架構的哪一層、AST10 跟你已經看過的清單怎麼分工、官方資料有哪兩處需要小心。

1.2 技能夾在哪一層

白皮書的 Key Terminology 把四個容易混在一起的詞分開。以下用作者自己的話整理：

  • 技能 (Skill)：一個自成一體、Agent 可以自動發現的指令與資源包，核心是 SKILL.md 加上它的檔案，Agent 會把它載入脈絡 (context)。SKILL.md 開頭有一段中繼資料，稱為 frontmatter，載入器常在使用者動手之前就會解析它。
  • 工具 (Tool)：Agent 直接呼叫的單一函式。
  • MCP 伺服器 (MCP server)：另一個行程，透過 Model Context Protocol 提供工具與資源。官方明說它由 MCP Top 10 涵蓋，不在 AST10 的範圍。
  • 外掛／擴充 (Plugin or extension)：特定宿主專用的安裝單位，可能打包一個或多個技能或工具。

1.4 核心概念：技能為什麼不是「又一種套件」

指令與程式住在同一個檔案

是什麼
技能同時攜帶兩種「可執行」的東西：程式碼層（腳本、一般程式的函式呼叫）與自然語言指令層（markdown 散文，教 Agent 做什麼）。官方每一條都用「Why It's Unique to Skills」說明這件事。
為什麼會發生
套件管理生態有簽章、鎖定檔、掃描器等成熟機制，但它們是為「程式碼」設計的。技能的另一半是文字，而且載入後以 Agent 的完整權限被「照著做」。官方條目指出：沒有可以釘住一份文件雜湊值的欄位，也沒有「散文的鎖定檔」。
怎麼被利用（概念層級）
攻擊者不一定要寫惡意程式；一段看似無害的指令，叫 Agent 把某個檔案送到某個位址，就能達到與一行腳本相同的效果，卻不含任何可被特徵比對的程式碼。教材不提供任何實際內容。
怎麼防
沒有單一解。官方分散在十條裡：來源可驗證（簽章、釘選）、權限最小化並在執行期強制、隔離、掃描指令層與程式碼層、治理與稽核。第 3 章會整理這些主題。
常見誤解
「技能就是提示詞，不是軟體，所以不用做供應鏈管理。」技能會以宿主 Agent 的權限執行或影響執行；官方的立場正好相反，把它當作需要簽章、釘選、審查的軟體製品。另一個誤解是：「用 MCP 就等於處理了技能風險。」官方明說 MCP 談的是溝通方式，技能實際做的事不在 MCP 的範圍。

1.5 官方資料裡的兩處內部不一致

這份文件還很新，且有不同版本的內容並存。你在引用時，必須先知道這兩點，否則容易引用到官方自己已經改掉的說法。

不一致 1：嚴重度

GitHub 的 README 與每個條目檔（ast01.md 到 ast10.md）都標了嚴重度：AST01、AST02 為 Critical，AST03 到 AST06 為 High，AST07 到 AST10 為 Medium。但較新的白皮書（GitHub 2026-08 更新）明說：不為個別風險指派嚴重度，要等 AIVSS v1（預計 2026 年底）可用之後再說。依「以最新來源為準」，本教材不採用這些嚴重度，也不依它排序；兩處的差別記在參考資料頁。

不一致 2：對 LLM Top 10 的編號沒有帶年份

白皮書每條的 OWASP Mapping 寫 "LLM03 (Supply Chain)"、"LLM09 (Misinformation / Excessive Agency)"、"LLM08 (Excessive Agency)" 這類編號，都沒有年份。同樣是 Excessive Agency，有的條目寫 LLM09、有的寫 LLM08；對照 LLM Top 10 2025 與 2026，兩者的 Excessive Agency 編號分別是 LLM06 與 LLM03，都對不上。這部分在第 4 章處理，這裡只先提醒：別照抄 AST10 裡的 LLM 編號。

本章重點與自我檢核

  • AST10 談的是 Agent 載入的「技能」這一層；官方口訣是 MCP 管溝通方式、AST10 管那些工具實際做什麼。MCP 伺服器本身由 MCP Top 10 涵蓋。
  • 現行標示：Incubator、1.0-2026；白皮書 V1 公開審查中，不是定稿。
  • 技能把自然語言指令與可執行程式放在同一個製品，這是它與一般套件供應鏈最大的差別。
  • 官方資料有兩處內部不一致：嚴重度（GitHub 有、白皮書說不指派）與 LLM 編號（沒有年份且彼此不一致）。
  • 我能用一句話說明 AST10、MCP Top 10、Agentic Top 10 各管哪一層。
  • 我知道為什麼技能不能只當作「提示詞」處理。
  • 我知道不該引用 AST10 的嚴重度排序，也不該照抄它的 LLM 編號。
