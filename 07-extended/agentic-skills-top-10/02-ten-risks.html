第 2 章　十項風險與歸類

十個條目按編號背很吃力，但官方白皮書其實已經替你分好組：它依「風險主要出現在技能生態的哪個部分」把十項分成四個面向。這一章先用這四個面向記住十項，再介紹官方給的歸類決策樹，最後拆解最容易混淆的一組：AST02 與 AST05。

2.1 十項風險一次看

下表的「官方一句話」是作者依 GitHub 條目檔的 Description 改寫的摘要，不是逐字翻譯。「面向」欄取自白皮書 Executive Risk Map 的官方分組。

表 2-1　AST01–AST10、官方面向與重點
編號與名稱官方面向官方描述重點
AST01 Malicious Skills
(惡意技能)		來源與登錄信任攻擊者發佈看似正常、實則含隱藏惡意內容的技能，可能藏在 SKILL.md 的文字裡。
AST02 Supply Chain Compromise
(供應鏈遭入侵)		來源與登錄信任技能登錄庫缺少成熟套件生態具備的來源驗證；攻擊者利用大量上傳、相依性混淆、帳號接管、儲存庫投毒。
AST04 Insecure Metadata
(不安全的中繼資料)		來源與登錄信任技能的名稱、描述、權限宣告等中繼資料是攻擊者可控的輸入：語意層可偽冒或低報權限，解析層可因不安全的反序列化在載入時執行內容。
AST03 Over-Privileged Skills
(權限過大的技能)		執行邊界技能拿到的權限超過其功能所需；一個合法技能可被下游的提示詞注入利用去做它原本不會做的事。
AST05 Untrusted External Instructions
(不受信任的外部指令)		執行邊界技能指向外部文件（API 說明、SDK 指南），Agent 在執行時讀取並照做；該內容可變動，且在技能的簽章與釘選機制之外。
AST06 Weak Isolation
(隔離薄弱)		執行邊界技能與宿主 Agent 在同一個安全情境執行（完整檔案、shell、網路權限），沙箱不存在、可選或預設關閉。
AST07 Update Drift
(更新漂移)		生命週期治理技能裝了就忘；沒有不可變的釘選與更新驗證，已部署的技能與已知良好版本脫節，或自動更新盲目吃下惡意變更。
AST08 Poor Scanning
(掃描不足)		生命週期治理為傳統程式碼設計的掃描工具，對混合自然語言與程式的技能效果差，讓惡意技能通過所有現有檢查。
AST09 No Governance
(缺乏治理)		生命週期治理組織缺少技能的清單、政策、審查與稽核軌跡，技能由個別開發者安裝，形成安全團隊看不見的「影子 AI」層。
AST10 Cross-Platform Reuse
(跨平台重用)		跨平台重用技能在不同平台間移植時，安全屬性（例如權限清單）沒有跟著轉換而遺失。

2.3 官方決策樹：這個發現歸哪一條

白皮書指出，幾個條目在實務上會重疊，所以附了一棵歸類決策樹，給「要為一個發現選出主要條目」的人使用。整理如下（官方只涵蓋這四個條目）：

表 2-2　官方決策樹 (Classifying and Triaging Findings) 的四步
步驟問題若是，歸為
1技能本身在發佈當時就是惡意的嗎？（隱藏負載、竊取憑證、後門）AST01 惡意技能
2發現是關於技能如何進入登錄庫或管線嗎？（仿冒名稱、缺簽章、發佈者審查薄弱、發佈者帳號被接管）AST02 供應鏈
3發現出在 SKILL.md 或 manifest 的中繼資料本身嗎？（誤導的描述、低報權限、偽造風險等級、frontmatter 的不安全反序列化）AST04 不安全的中繼資料
4是掃描或審查控制本該攔下卻沒攔下嗎？（自然語言繞過、混淆指令、冒充掃描器）AST08 掃描不足

官方還有一條規則：多個條目同時成立時，把「主要根因」記為源頭條目，把掃描缺口記為「促成的控制失效」，不要把一個發現拆成兩筆。例如，一個惡意技能同時躲過了掃描器，記為 AST01，並註記 AST08 是促成因素。

2.4 核心概念：AST02 與 AST05 的邊界

技能本身 vs. 技能指向的內容

是什麼
AST02 處理的是程式碼與相依性這條供應鏈：它可以被簽章、被雜湊釘選。AST05 處理的是技能指向的文件：Agent 在執行時才去讀、而且會照著做。官方在 AST05 的交叉引用裡明說，這是 AST02 的完整性控制「管不到」的部分。
為什麼會發生
你可以簽章並釘住技能這個資料夾，卻沒辦法簽章「某個網址在執行時回傳什麼」。官方的說法是：沒有欄位可以釘住一份文件的雜湊，沒有「散文的鎖定檔」，簽章技能對該網址的內容什麼也沒說。
怎麼被利用（概念層級）
官方列了幾種形態：作者先發佈無害的技能，通過審查與掃描、被信任並部署之後，再修改它所指向的文件（作者反悔）；被指向的網址對審查者與掃描器回傳乾淨內容、對真正執行的 Agent 回傳不同內容（審查者被騙）；被指向的文件再指向更多外部資源，攻擊者只要控制鏈上很深的一個連結（傳遞性參照）。教材不提供實作細節。
怎麼防
官方建議：在審查時記錄每份外部文件的內容雜湊，每次載入時重新驗證；盡量把外部文件在發佈時「內嵌」進簽章過的技能包；用網域允許清單限制可抓取的來源；把參照鏈視為攻擊面的一部分傳遞性地審查；維護整個機隊的外部來源清單；持續重新掃描。
常見誤解
「技能已經簽章並釘住，所以它是安全的。」這只證明技能這包檔案沒變，不代表它在執行時讀到的外部內容沒變。另一個誤解是：「AST05 就是 AST04 的另一種說法。」官方區分：AST04 是透過解析技能自己的檔案執行負載；AST05 不需要任何程式執行，Agent 只是照著外部文字的指示行動。

本章重點與自我檢核

  • 官方四個面向：來源與登錄信任（AST01、02、04）、執行邊界（AST03、05、06）、生命週期治理（AST07、08、09）、跨平台重用（AST10）。
  • 官方決策樹只有四步（AST01 → AST02 → AST04 → AST08）；多個同時成立時，記主要根因為源頭條目，掃描缺口當作促成因素，不拆成兩筆。
  • AST02 管得到程式碼與相依性（可簽章、可釘選）；AST05 管不到的是執行時才讀取的外部文件。
  • AST05 與 AST04 的區別：AST04 靠解析技能自己的檔案執行負載；AST05 只靠外部文字的指示，不需要程式執行。
