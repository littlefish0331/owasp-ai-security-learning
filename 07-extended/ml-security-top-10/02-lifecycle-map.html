第 2 章　十項風險地圖

  • 預估閱讀：約 6 分鐘（不含章末檢核；另有 4 題章末檢核）
  • 對應學習目標：LO2

十個條目照編號讀很容易背不起來，也看不出彼此的關係。這一章換一個角度：問「攻擊者是在哪一段碰到你的系統」。依這個問題，十項風險自然分成三組，你也會看出哪幾組名稱像、但打擊的目標完全不同。

2.1 十個條目一次看

下表是專案頁列出的十項。「官方一句話」是作者依各條目頁的 Description 改寫的摘要，不是逐字翻譯。

表 2-1　ML01:2023–ML10:2023 與官方描述重點
編號與名稱官方描述重點
ML01:2023 Input Manipulation Attack
(輸入操縱攻擊)		涵蓋對抗樣本；攻擊者刻意微調輸入，讓模型誤判。官方稱它是「涵蓋多種攻擊的上位詞」。
ML02:2023 Data Poisoning Attack
(資料投毒攻擊)		攻擊者竄改訓練資料，使模型行為偏離預期。
ML03:2023 Model Inversion Attack
(模型反推攻擊)		攻擊者對模型做逆向，取出原本不該揭露的資訊（官方情境：從人臉辨識模型取回個人資訊）。
ML04:2023 Membership Inference Attack
(成員推論攻擊)		判斷某筆資料是否在訓練集中，進而推知敏感資訊（見 2.4 的說明：官方描述文字與情境不一致）。
ML05:2023 Model Theft
(模型竊取)		攻擊者取得模型的參數。
ML06:2023 AI Supply Chain Attacks
(AI 供應鏈攻擊)		攻擊 ML 專案依賴的函式庫、MLOps 平台、資料與模型管理工具、模型庫。條目頁標題寫成 "ML Supply Chain Attacks"，見參考資料頁。
ML07:2023 Transfer Learning Attack
(遷移學習攻擊)		攻擊者先在某個任務訓練模型、再微調到另一個任務，使目標系統帶入有害行為。
ML08:2023 Model Skewing
(模型偏斜)		攻擊者操縱訓練資料的分佈，通常透過回饋迴路餵入假資料。
ML09:2023 Output Integrity Attack
(輸出完整性攻擊)		攻擊者竄改模型的輸出，使下游系統受害。
ML10:2023 Model Poisoning
(模型投毒)		攻擊者直接竄改模型的參數，使其產生有害結果。

2.2 依生命週期分三組

官方是以編號列出，沒有分組。下圖是作者依「攻擊者最先碰到系統的哪一段」整理的分組，用來幫助記憶。分組是作者整理，非官方。有些條目橫跨兩段，圖中放在它最典型的位置。

2.3 兩組最容易混淆的條目

看名稱很容易混淆的有兩組。判斷的竅門只有一個：問「攻擊者動的是什麼」——是動了資料、動了模型本身，還是只拿模型的輸出去推論別的東西。

表 2-2　容易混淆的條目：攻擊者動的是什麼
條目攻擊者動的是結果發生時機
ML02 資料投毒訓練資料模型從壞資料學到壞行為訓練期
ML10 模型投毒模型參數本身模型被直接改寫（官方情境：改變辨識結果的數字）模型存在之後
ML03 模型反推對模型的查詢與輸出從輸出推回輸入端的敏感資訊推論期
ML04 成員推論對模型的查詢與輸出判斷某筆資料在不在訓練集推論期

資料投毒與模型投毒的差別，等於「污染食材」與「直接改食譜」：前者讓模型自己學壞，後者不經過學習、直接改模型檔案裡的數字。模型反推與成員推論都是「不改任何東西，只從輸出推論」，差別在推論的目標：反推是取回資料內容，成員推論只回答「這筆在不在」。

2.4 核心概念：成員推論 vs. 模型反推

只靠查詢就能洩漏什麼

是什麼
兩者都是「攻擊者只能對模型提問，不能改動它，卻想知道訓練資料的事」。成員推論 (Membership Inference)：判斷某人的資料是否在訓練集；模型反推 (Model Inversion)：從模型輸出推回輸入端的資訊。
為什麼會發生
模型對它訓練過的資料常表現得比沒見過的資料「更有把握」。官方的防禦建議也圍繞這件事：減少過擬合（正則化）、降低輸出透露的資訊量（加入雜訊或差分隱私）、縮減訓練資料。
怎麼被利用（概念層級）
官方 ML04 的情境：攻擊者想知道某人是否出現在一份金融紀錄資料中，就用模型查詢來推斷。官方 ML03 的情境：對人臉辨識模型取回與個人有關的資訊。教材不提供查詢步驟。
怎麼防
ML03 的建議偏向限制誰能問、問什麼：存取控制、輸入驗證、記錄輸入輸出、監控輸出分佈。ML04 的建議偏向讓模型更不暴露訓練痕跡：隨機化訓練資料、輸出模糊化、正則化、縮減資料。
常見誤解
「只要模型不公開權重就沒事。」兩者都只需要查詢能力。另外要小心：官方 ML04 的 Description 一句話寫成「攻擊者操縱訓練資料使模型洩漏敏感資訊」，這更像資料投毒；但它的預防措施與情境都是「判斷某筆資料是否在訓練集」。本教材依預防措施與情境，並與 AI Exchange 的成員推論一致來理解。

本章重點與自我檢核

  • 用「攻擊者動的是什麼」分辨：資料（ML02）、模型參數（ML10）、只對模型提問（ML03、ML04）。
  • 三組：資料與訓練期（ML02、ML07、ML08）、模型與供應鏈（ML05、ML06、ML10）、推論期（ML01、ML03、ML04、ML09）。分組是作者整理，非官方。
  • ML08 的攻擊入口是部署後的回饋迴路，但改變的是訓練資料分佈。
  • 官方 ML04 的 Description 與其預防措施、情境用字不一致；本教材依預防措施與情境理解。
  • 我能在不看表的情況下，說出十項各自的一句話描述。
  • 我能分辨資料投毒與模型投毒，並說出各自的防禦方向。
  • 我知道成員推論與模型反推的差別，以及官方 ML04 描述的不一致。
