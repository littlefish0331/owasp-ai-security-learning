第 3 章　BOM 家族與整合

  • 預估閱讀：約 7 分鐘（不含章末檢核；另有 3 題章末檢核）
  • 對應學習目標：LO3
  • 前置：第 2 章

讀到這裡，你已經遇到四個長得很像的縮寫：SBOM、AIBOM、DBOM、AgBOM。它們出自不同文件，各自管不同範圍，卻都用同一種「物料清單」的概念。這一章把它們並排，整理其他官方文件對 BOM 的要求，並指出一個容易忽略的細節：OWASP 自己的文件引用的 CycloneDX 版本並不一致。

3.1 四種清單，管不同範圍

AIBOM／AI-BOM／ML-BOM

AgBOM
(Agent Bill of Materials)		Agent 的即時清單：模型、工具、相依；工作階段中可變動（可換模型、工具、MCP 伺服器）Agent Control Standard 的 Inspect 支柱Guardian 依請求序列化為 CycloneDX 1.6、SPDX 3.0 或 SWID 之一

三份文件，三個 CycloneDX 版本

AIBOM Generator 輸出 CycloneDX 1.6；ACS 規格寫 AgBOM 可序列化為 CycloneDX 1.6、SPDX 3.0 或 SWID；資料安全 2026 建議 DBOM 以 CycloneDX ML-BOM（ECMA-424，v1.7）為基礎。這不一定是矛盾：一個是工具實際輸出，一個是規格允許的序列化，一個是建議的基礎格式。但如果你要把三種清單串在同一條管線，就要確認版本相容。官方沒有說明三者如何互通，本教材未能確認。

3.2 各份官方文件對 BOM 的要求

本階段涵蓋的 OWASP 文件中，有四份對物料清單提出了明確的要求。下表依「要求的強度」整理，用詞盡量貼近官方原意：

表 3-2　各份官方文件對 BOM 的要求
文件清單種類官方怎麼說
GenAI Incident Response Guide 1.0AI-BOM設計階段建立產生要求；建置時自動產生並在 CI/CD 閘門強制執行；靜態偵測的基礎技術，視為高信任環境的前提；事件後重新產生驗證；事後更新
Data Security Risks and Mitigations 2026DBOM在 DSGAI04 稱它是「讓其他每一項緩解措施都可追溯與可稽核的基礎產物」，歸 Tier 2、範圍為 Build；DSGAI10 的 Tier 1 有「Dataset Bill of Materials」；DSGAI21 要求加上完整性證明記錄
Agent Control Standard v0.1.0AgBOM屬 ACS-Inspect 設定檔，不屬 ACS-Core（Core 明確不要求 AgBOM）；宣告 ACS-Inspect 的部署要在每個工作階段、內容相關鉤子觸發之前，送出一次 agbom/snapshot；工作階段中換模型、工具或 MCP 伺服器的部署，要用 ACS-Inspect-Dynamic 的 agbom/changed。「當 Guardian 的政策依賴元件清單時為必要」
Agentic Skills Top 10 白皮書簽署的 AI BOM在 AST02 的 OWASP Mapping 引用 AISVS v1.0-C6.2.2 (signed AI BOMs)；AST09 的治理建議含技能清單（名稱、版本、雜湊、安裝者…）

有一個細節值得停下來想：「清單」在不同文件的強制程度很不一樣。IR 指南說它是「高信任環境的前提」；資料安全把 DBOM 放在 Tier 2（需要架構調整，而不是一個 sprint 的事）；ACS 則把 AgBOM 放在選用設定檔，而且 ACS 的符合性是自行宣告、無人驗證。換句話說，「要有物料清單」這個共識很強，但「何時該做到、做到多細」並沒有統一標準。

3.3 核心概念：清單回答的是「靜態」還是「動態」

靜態清單與即時清單

是什麼
AIBOM Generator 產生的是某個時間點對某個模型的清單；ACS 的 AgBOM 是 Agent 的即時清單，在 Agent 運作中隨元件變動而更新。前者像出貨時的裝箱單，後者像會隨時修改的庫存系統。
為什麼這個差別重要
Agent 可以在執行中載入技能、連到新的 MCP 伺服器、換模型。ACS 因此特別設了 agbom/changed：官方說，對「Agent 會熱插拔模型、工具或 MCP 伺服器」的部署，這是必要的。如果只有出貨時的靜態清單，這些執行期變動就看不見。
對安全的含意（概念層級）
技能與 MCP 伺服器的變動，正是 Agentic Skills Top 10 的更新漂移 (AST07) 和供應鏈 (AST02) 所關注的面向。把 AgBOM 的動態更新與 AST07 連起來看，是作者整理，非官方：官方沒有寫兩者的對應。
怎麼用
看你的系統是否在執行期改變組成。若是，只靠建置時的清單不夠；若否（模型與依賴固定），建置時產生並在 CI/CD 強制，已經涵蓋大部分情況。
常見誤解
「AgBOM 就是 AIBOM 的新名字。」兩者範圍不同：AIBOM Generator 針對 Hugging Face 上的模型；AgBOM 是 ACS 的 Agent 即時清單，描述 Agent 用的模型、工具與相依。官方頁面沒有說明兩者的關係，未能確認它們是否會互通。

3.4 與本階段其他主題的連結

  • ML Top 10：ML06（AI 供應鏈攻擊）談攻擊面，條目頁沒有提到物料清單。官方沒有把 AIBOM 對映 ML06，兩者概念相鄰是作者整理，非官方。
  • Agentic Skills Top 10：見表 3-2；技能清單（AST09）與簽署的 AI BOM（AST02 對應 AISVS C6.2.2）。
  • Agent Control Standard：AgBOM 的出處；ACS 的 conformance 文件寫道：AgBOM 已列出 skill 元件的部署「應該」(SHOULD) 發出技能生命週期鉤子，免得 Guardian 對清單已經暴露的組合面毫無所知。這代表清單與執行期控制點可以互相支撐。
  • 資料安全：DBOM 的出處；刪除請求後的衍生物難題，正好是 DBOM 想回答的「這個嵌入來自哪筆來源」。
  • 事件應變：在事件的每個階段使用 AI-BOM，見表 3-2。

3.5 全主題重點與自我檢核

  • AIBOM 是物料清單，不是安全檢測；完整度分數衡量文件完整度，不是模型安全。
  • OWASP AIBOM Generator 輸出 CycloneDX 1.6，只涵蓋 Hugging Face 上的模型，版本未能確認，現行入口 owasp-genai-aibom.org，授權 Apache-2.0。
  • 四種清單：SBOM（軟體）、AIBOM（模型與相依）、DBOM（資料與血緣）、AgBOM（Agent 即時組成）；各自範圍與格式不同。
  • IR 指南稱 AI-BOM 是高信任環境的前提並要求事件後重新產生；資料安全稱 DBOM 是其他緩解的基礎；ACS 的 AgBOM 屬選用設定檔。
  • 三份文件引用的 CycloneDX 版本不同（1.6、1.6、1.7），互通性官方未說明。
  • 我能說出四種清單各管什麼，以及各出自哪份文件。
  • 我能說明為什麼 Agent 需要「即時」清單。
  • 我知道哪些 BOM 對映是官方明載，哪些是作者整理。
