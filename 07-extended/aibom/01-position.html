「AIBOM」這個詞在 OWASP 底下指的其實有兩件事：一個是專案 (AI SBOM Initiative)，一個是這個專案維護的工具 (AIBOM Generator)。這一章把兩者分開、說明工具的範圍，並指出幾個你可能踩到的坑：入口網址有兩個、版本不明、以及「完整度分數」的真正意思。

1.3 範圍：只涵蓋 Hugging Face 上的模型

官方在多處反覆強調同一個範圍：工具「從開源的 Hugging Face 模型開始」(starting with open models on Hugging Face)。它從模型卡 (model card)、設定檔與儲存庫檔案抽取中繼資料。換句話說，它不是通用的 AI 物料清單產生器：

  • 它不涵蓋你自己訓練、沒放在 Hugging Face 的模型。
  • 它不涵蓋 RAG 語料、向量資料庫、嵌入模型的版本連結（這些屬資料安全文件提出的 DBOM，見第 3 章）。
  • 它不涵蓋 Agent 的工具與技能組成（這些屬 ACS 的 AgBOM，見第 3 章）。

CLI 還有兩個選項值得知道：--inference 可以「用 AI 推論強化中繼資料」（需要 API 金鑰），--summarize 可以做描述摘要。也就是說，產出的清單中，某些欄位可能是由 AI 推論補上的，而不是模型卡原本就寫的。官方 README 沒有說推論補上的欄位是否有特別標示，本教材也沒有實際執行比對，這一點未能確認；使用時應自行檢查來源。

1.4 核心概念：完整度分數衡量的是「文件完整度」

分數高 ≠ 模型安全

是什麼
工具會對產生的 AIBOM 做「欄位檢核」並給出完整度分數 (completeness score) 與改善建議。官方資源頁的說法是用來「評估 AIBOM 的品質與覆蓋度」。
為什麼會有人誤解
「分數」很容易讀成「評分」。但這個分數衡量的是：模型卡等來源有沒有把該填的欄位填齊，也就是物料清單這份文件本身完整不完整，不是模型有沒有後門、資料有沒有被投毒。
對安全的含意（概念層級）
一份資料齊全的清單，可以在一個被投毒的模型上拿滿分；反過來，一個很安全的模型也可能因為模型卡寫得簡略而分數低。清單提供的是可追溯性：出事時你能回答「用了什麼、從哪來」。這與 LLM Top 10 供應鏈主題的原則一致：簽署證明來源，不證明安全。
怎麼用
把它當作「補欄位的工作清單」與「盤點的起點」，而不是「通過／不通過」的門檻。官方沒有公布評分公式，所以你也不能把分數當成可比較的量化指標。
常見誤解
「我們模型的 AIBOM 完整度 95 分，所以供應鏈是安全的。」分數只反映文件完整度。另一個誤解是：「有了 AIBOM 就不用做模型掃描與簽章驗證。」物料清單與簽章、掃描是不同的控制，第 3 章會說明各文件怎麼要求。

本章重點與自我檢核

  • OWASP AIBOM 有兩個層次：專案（AI SBOM Initiative，屬 GenAI Security Project）與工具（AIBOM Generator，儲存庫授權 Apache-2.0）。
  • 工具現行入口是 owasp-genai-aibom.org（部落格與 README），資源頁下載連結仍指向 Hugging Face Space；版本未能確認。
  • 工具只支援 Hugging Face 上的模型，輸出 CycloneDX 1.6；不涵蓋資料、RAG 或 Agent 組成。
  • 完整度分數衡量的是文件完整度，不是安全性；官方沒有公布評分公式。
  • 我能分辨 AIBOM Initiative 與 AIBOM Generator。
  • 我知道工具的範圍限制，以及為什麼不能用它盤點整個 AI 系統。
  • 我能說明完整度分數為什麼不等於安全。
