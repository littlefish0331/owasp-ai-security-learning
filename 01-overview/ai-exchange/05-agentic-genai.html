第 5 章　GenAI 與 Agentic AI

  • 預估閱讀：約 10 分鐘（不含章末檢核；另有 4 題章末檢核）
  • 對應學習目標：LO5
  • 前置：第 4 章

AI Exchange 的立場有點出人意料：從威脅角度看，生成式 AI 與其他 AI「沒有那麼不同」。本章先看 GenAI 真正新的是什麼，再看 agent 為什麼把風險從「錯誤的答案」變成「錯誤的行動」。

5.1 GenAI 與其他 AI 的差別

官方在「How about Generative AI?」一節的重點是：GenAI 與一般 AI 的威脅與控制大部分重疊；有些風險更高、有些更低，只有少數是 GenAI 特有的。差別主要在資料科學類的控制（例如對訓練集加雜訊），以及很多 GenAI 系統直接使用現成模型、不由組織自行訓練，使部分安全責任轉移到供應商。

官方列出九項 GenAI 的安全特性，並對照到 LLM Top 10。下表是整理後的對照（編號為官方在總覽頁引用的 2026 版編號，本教材已對照 GitHub 的 2026 版清單確認編號與名稱一致）。

5.2 Agentic AI：風險從「錯誤的答案」變成「錯誤的行動」

官方對 Agentic AI 的定義：模型的推論可以指定要執行的動作，而不需要每個動作都經過人工核准，不只是提供輸出讓人檢視。官方強調 Agentic 是一個光譜，不要用單一方式看待：

官方把光譜分成四級：輕度（會執行動作，例如開門的 AI 攝影機）、中度（還會規劃）、相當（還會在迴圈中運行）、高度（以上全部，且沒有人類介入）。

官方建議直接看系統的屬性：模型能不能觸發動作、能造成什麼傷害、有沒有不可信資料進來、有沒有用記憶、動作能不能把資料送出去。

致命三要素

官方在 agentic 概觀與風險分析兩處都提到：要發生敏感資料外洩，需要同時有三件事：

  1. Data（資料）：攻擊者能控制某些資料，它在使用者的 session 中的某個時刻進入 LLM，用來做間接提示詞注入；
  2. Access（存取）：該 LLM 或相連的 agent 能存取敏感資料；
  3. Send（送出）：該 LLM 或相連的 agent 能主動把資料送出去給攻擊者。

風險分析的直接應用

官方用這個概念說明為什麼「理論上存在」不等於「必須處理」：若 agentic 系統用了 LLM，理論上就有間接提示詞注入；但如果你唯一擔心的是公司敏感資料外洩，而系統沒有任何能把資料送給攻擊者的途徑（例如沒有寄信功能、輸出也不被渲染成可點擊內容），這個風險就停留在理論層級，不需要處理。第 7 章會把它放回完整的風險分析流程。

四條安全架構原則

官方強調這是「設計約束」，不是另一套控制清單：

  • 在基礎設施強制，而不是在提示詞裡（最小模型權限、模型存取控制、agent 沙箱）。
  • 為組合式行為而設計：工具與多步串接的流程空間太大，無法事先完整規定，所以需要執行期護欄。
  • 假設會跨層連鎖：資料、推理、工具、API 與其他 agent 是同一個組合式攻擊面 (Attack Surface)。
  • 預設限制爆炸半徑 (Blast Radius)：預設拒絕的工具存取、不可轉移的 session、agent 之間不傳遞信任。

5.3 核心概念：越獄 (Jailbreak) 與逃逸 (Agent Escape)

越獄與 Agent 逃逸：不同層的問題

是什麼
越獄是在 agent 的邊界之內，突破模型的安全限制（例如被要求拒絕的有害內容）。逃逸是 agent 超出它被定義的邊界：呼叫未授權的工具、存取範圍外的系統、做超出任務的事。
為什麼需要區分
官方：越獄主要是推理層的問題，逃逸主要是基礎設施層的政策強制問題。把兩者混為一談，產生的控制只能部分有效。
怎麼被利用（官方範例，概念層級）
官方範例：程式碼執行 agent 在多輪對話中被逐步「重新框架」，到第八輪嘗試列舉檔案系統，這是它在第一輪會拒絕的事。
怎麼防
逃逸：在後端以能力為基礎的存取控制限制工具、資料來源與動作範圍，與 LLM 的推理無關（LEAST MODEL PRIVILEGE）。越獄：用 session 層級的 OVERSIGHT 偵測漸進式偏移。
常見誤解
「擋住越獄就等於擋住了 agent 出事。」官方明說：基礎設施層的強制可以在越獄於推理層得逞時，仍然阻止逃逸。但也有限制：授權範圍很廣的 agent，即使不逃逸，也可能透過越獄造成傷害。

5.4 和 Agentic Top 10 的邊界

兩份 OWASP 文件都談到邊界，說法一致：

  • LLM Top 10 2026 的前言：當模型只是應用中的元件時，風險歸這份清單；一旦模型成為「行動者」，帶著工具、跨 session 的記憶、與下游後果，風險就移到 OWASP Agentic Top 10。許多事件正好落在這個邊界上，兩份要搭配讀。
  • LLM03:2026 Excessive Agency 說明：在 agentic 系統中，它可能表現為 ASI02（Tool Misuse and Exploitation）、ASI03（Identity and Privilege Abuse）與 ASI08（Cascading Failures）。這是官方明載的對應。
  • 分類視角不同：AI Exchange 把目標劫持 (Goal Hijacking) 視為「影響」，攻擊向量仍是提示詞注入及相關路徑；Agentic Top 10 則將它列為獨立條目 ASI01 Agent Goal Hijack。這不是矛盾，是切分方式不同。

5.5 情境範例 B：履歷篩選 Agent

情境 B（虛構）：晨光人資的履歷篩選 Agent

虛構 晨光人資是虛構的公司。他們部署了一個履歷篩選 agent：從應徵信箱讀取履歷附件、查詢內部人才庫（含現任員工的薪資帶與考績摘要，供「是否內部轉調」比對）、產出評估後寄給招募主管，並能依評分自動發送面試邀約。

架構：外部履歷（不可信）→ agent（LLM）→ 內部人才庫（敏感）→ 郵件 API（可對外寄信）。

  1. 發生了什麼：某份履歷的檔案裡，含有人眼看不到、但模型會讀到的指示，要 agent 把人才庫中的某些資料附進給招募主管的信件，並同時抄送外部信箱（概念層級，不描述具體做法）。
  2. 哪一環出問題：同時具備致命三要素：Data＝外部履歷；Access＝人才庫含敏感資料；Send＝郵件 API 可對外寄信。三者都未被隔離。
  3. 對應條目：AI Exchange：Indirect prompt injection 與 Excessive Agency 一類風險；LLM Top 10 2026：LLM01 Prompt Injection（間接）與 LLM03 Excessive Agency；因為已是 agent，Excessive Agency 在 Agentic Top 10 對應 ASI02／ASI03／ASI08。
  4. 該採什麼控制：
    • 拆掉其中一項（Rule of Two）：讓處理履歷的 agent 看不到人才庫，把「比對內部轉調」拆成另一個沒有對外寄信權限的步驟；
    • LEAST MODEL PRIVILEGE：agent 的郵件權限限定為寄給固定的招募主管名單，不能寄到外部；面試邀約改由人核准；
    • OVERSIGHT：偵測「評估任務卻附入非必要的人才庫資料」或「新的外部收件人」；
    • DATA MINIMIZE：人才庫中的薪資與考績摘要若非必要，就不要讓這個 agent 取得。
  5. 學到什麼：與其在「模型會不會被騙」上賭，不如先檢查「如果被騙了，它能拿到什麼、送出去什麼」。這正是第 7 章風險分析要練的思路。

本章重點與自我檢核

  • GenAI 與其他 AI 的威脅大部分重疊；GenAI 特有的重點是提示詞注入、超大訓練集、對雲端與 RAG 的依賴，以及輸出可能含注入。
  • LLM Top 10 並非窮盡：輸入資料外洩就未被涵蓋。
  • Agentic = 模型推論可以直接指定動作；風險從錯誤答案變成錯誤行動，爆炸半徑控制是關鍵。
  • 致命三要素：攻擊者可控的資料 + 能存取敏感資料 + 能送出資料。移除任一項即可中斷。
  • 在基礎設施強制授權，而不是在提示詞裡；越獄是推理層問題，逃逸是政策強制問題。
  • 我能對一個 agent 檢查致命三要素，並提出拆掉哪一項的方案。
  • 我能說出 Excessive Agency 在 agentic 系統中對應到哪三個 ASI 條目。
  • 我知道 LLM Top 10 與 AI Exchange 在「輸入資料外洩」上的差別。
