LLM Top 10 告訴你「有哪些風險」。下一個很自然的問題是：「市面上有哪些工具能處理它？」Solutions Landscape 就是 GenAI Security Project 對這個問題的回答。本章教你怎麼讀它、怎麼用它，以及它不能做什麼。

4.2 核心：SecOps 九階段

Landscape 的目錄並不是依「攻擊類型」排列，而是依 LLM／GenAI 應用的生命週期階段排列。這是它和 LLM Top 10 最不同的地方。Reference Guide 說明：它以 DevOps → DataOps → MLOps → LLMOps 為基礎，並在 LLMOps 上加上資安 (LLMSecOps)。

表 4-3　九階段各階段的重點（Reference Guide 的階段說明，改寫；階段中的具體安全任務請看官方 PDF）
階段重點（官方描述，改寫）
Scope & Plan定義應用的目標與要解決的需求、決定預訓練模型如何整合進整體系統；蒐集需求、評估倫理與合規考量、訂出效能／擴展／互動目標
Augment & Fine-Tune Data客製化預訓練模型：用領域資料擴充原始資料集，再以重新訓練（微調）最佳化
Develop & Experiment把微調後的模型整合進應用架構：建置介面、互動與工作流，並實驗不同設定、依回饋改進
Test & Evaluate嚴格評估效能、安全與可靠性：功能、安全與可用性測試，確認 LLM 與應用整合順暢並符合需求
Release把完成的應用推向正式環境：最終部署策略、為擴展性與安全配置基礎設施、確認元件整合正確，設定監控與告警
Deploy安全地啟動 LLM 與相關元件：配置基礎設施、確認各項安全措施到位、驗證 LLM 與其他元件的整合
Operate管理並維護運作中的應用：持續監控效能、安全與使用者互動；回應事件、套用更新與修補
Monitor即時持續觀察效能、安全與使用者互動：追蹤指標、偵測異常、確認元件正常；也蒐集資料作為持續改進之用
Govern建立並落實政策、標準與最佳實務，確保應用在整個生命週期中安全且合乎倫理：資料使用、模型管理、合規與安全控制的治理框架

各階段在官方 PDF 速查表裡還有「具體安全任務清單」（例如 Test & Evaluate 階段：對抗式測試、偏誤與公平性測試、滲透測試等）。這些任務逐項列在官方圖上，本教材不逐項複製，請看原文。

4.4 使用限制：這一節最重要

不要把目錄當成「推薦清單」

是什麼
Landscape 是一份社群資源，列出了開源與商業的資安解決方案，並依生命週期階段與風險對照。
官方明說的限制
線上目錄頁寫：「這不是完整清單，也不是背書 (It is not a comprehensive list or an endorsement)。」Reference Guide 也寫：OWASP 不推薦或背書第三方網站的內容；它「並非設計成包羅萬象」。
官方沒有說、但資料裡看得到的事（需自行留意）
(a) 2026 Q2 的各份速查表 PDF，圖例上把開源、金級贊助商 (Gold Sponsors)、銀級贊助商 (Silver Sponsors) 分開標示。(b) 2025 年的 Reference Guide 在部分商業解決方案後面直接註明「(Silver Sponsor)」。(c) 線上目錄頁本身本教材沒有看到贊助欄位，也沒有看到贊助對收錄或排序是否有影響的說明。所以本教材無法判斷贊助關係是否影響收錄，教材不做任何推論；你只需要知道這個標示存在。
所以怎麼用
把它當成「縮小候選的起點」：用領域、階段、風險標籤篩出類別，再自行評估。你仍然需要：確認產品實際涵蓋的風險與階段（目錄只是自述）、評估成本與整合、必要時做驗證測試（紅隊或廠商評估，見第 3 章的 AI Red Teaming）。
常見誤解
「在目錄上的產品就代表通過 OWASP 的認證／審核。」官方明確說不是背書。另一個誤解是「目錄上沒有的產品不好」：官方說目錄不完整，沒收錄不代表什麼。

另外值得知道的是，目錄頁有一個「Submit an Entry」的連結，指向 staging-b66e-genaiowasp.wpcomstaging.com/solution-submission/，這是一個 staging（測試環境）網址，疑似官方站設定問題；教材不建議你直接使用，要提交時請先與官方確認。這是 2026-10-26 的觀察，之後可能已修正。

4.5 情境範例 B：用 Landscape 縮小候選

情境 B（虛構）：弘毅醫療的客服 agent 採購評估

虛構 弘毅醫療是虛構的公司。他們要為客服 agent（會讀病患來信、查詢排程系統、代為預約）採購一套「執行期防護」產品。採購主管打開線上目錄，看到幾百筆解決方案，不知從何下手；另一位同事提議：「就挑目錄裡涵蓋最多風險標籤的那一個。」

  1. 先用領域與階段篩選：選「Agentic」領域；需求是執行期防護，對應階段是 Operate 與 Monitor（目錄顯示各約 85、93 筆）。這一步把候選縮小到「在這兩個階段有宣稱涵蓋」的產品。
  2. 再用風險標籤篩選：agent 會讀外部來信（不可信輸入）、查詢內部系統（敏感資料）、代為預約（變更狀態）。這三件事的風險，Agentic 標籤對應的是 Agentic Top 10 的條目。用 ASI 標籤把有宣稱涵蓋的產品列出。
  3. 哪裡會出問題：(a) 「涵蓋最多標籤」是廠商自述的涵蓋範圍，不等於實際防得住；(b) 目錄不是背書，不是 OWASP 的評比；(c) 圖例上有贊助商標示，但目錄並沒有說明贊助是否影響收錄，你不能據此判斷產品好壞。
  4. 該怎麼做：把篩選結果當成「長名單」，再自行訂定評估標準：先對自家系統做威脅建模（AI Exchange 的風險分析），確定需要防的是哪些風險；對候選產品要求提供證據；必要時用紅隊（AI Red Teaming 的評估廠商指引，Vendor Evaluation Criteria）驗證其宣稱。
  5. 學到什麼：目錄回答的是「有誰宣稱做什麼」，不是「誰做得好」。

本章重點與自我檢核

  • Solutions Landscape = 每季更新的解決方案指南（PDF 速查表）加線上目錄；官方稱它「不是完整清單，也不是背書」。
  • 它依 SecOps 九階段與四種應用型態組織：Scope & Plan → Augment & Fine-Tune Data → Develop & Experiment → Test & Evaluate → Release → Deploy → Operate → Monitor → Govern。
  • 線上目錄依領域、類型、階段與風險標籤篩選；風險標籤仍停在 LLM Top 10 2025／2023，且 2025 與 2026 編號不同。
  • 贊助商標示存在於 PDF 圖例與較早的 Reference Guide；贊助是否影響收錄，官方沒有說明，教材不推論。
  • 用它縮小候選；實際評估仍要自己做。

  • 我能解釋為什麼「在目錄上」不等於「經過 OWASP 認證」。
