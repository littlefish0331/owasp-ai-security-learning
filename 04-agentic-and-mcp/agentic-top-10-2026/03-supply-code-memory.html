第 3 章　供應鏈、程式碼與記憶（ASI04–ASI06）

  • 預估閱讀：約 7 分鐘（不含章末檢核；另有 4 題章末檢核）
  • 對應學習目標：LO3
  • 前置：第 2 章

上一章談的是 agent 怎麼使用東西。這一章換個角度：agent 用的東西本身出了問題。它的工具、外掛、提示範本來自第三方（ASI04）；它產生並執行的程式碼逃出了預期（ASI05）；它的記憶和脈絡被人動過手腳（ASI06）。三者都有「在 agent 判斷之前就已經被污染」的共同點。

三條共同的防線有兩個：在進入 agent 之前驗證（簽章、允許清單、寫入檢查），以及在執行之後隔離（沙箱、快照、緊急停用）。

3.2 核心概念：為什麼「活的供應鏈」跟傳統不同

活的供應鏈 (Live Supply Chain)

是什麼
agent 在執行期動態載入外部工具、提示範本、agent 描述 (agent card) 與外掛，而不是在部署前就固定好。這些元件的信任是在執行當下才決定的。
為什麼和傳統不同
傳統軟體供應鏈靠清單與簽章在建置時管，LLM03:2025 談的也以靜態相依為主。agent 的元件會在執行時被選擇、組合、委派，而且 agent 本身是長壽、有狀態的實體，單一元件被污染就能引發升權、行為漂移或跨 agent 的系統性誤用。
怎麼被利用（概念層級）
文件列的路徑：遠端載入的提示範本含隱藏指示；工具描述或 MCP／agent card 的中繼資料夾帶隱藏指示，被當作可信的引導；名稱相近的惡意工具冒充正牌工具；第三方 agent 或 MCP／登錄伺服器本身被入侵；被污染的知識外掛使 agent 逐漸偏誤。文件引用的公開事件包括 Amazon Q 外掛被植入破壞性提示並隨 v1.84.0 發布，以及在 npm 上被通報的冒充 postmark 的惡意 MCP 伺服器。
怎麼防
表 3-1 列了重點。若只能記一件事：可以被執行期載入的東西，都要有來源證明、固定版本，並能被一鍵停用。
常見誤解
「已經做了 SBOM，所以供應鏈沒問題。」文件在附錄 B 說得很清楚：CycloneDX 與 AIBOM 回答「我的 AI 系統裡有哪些元件與工具」；Agentic Top 10 與 AIVSS 回答「這些元件與自主 agent 可能怎麼行為、互動或失效」。清單是起點，不是結論。

3.3 情境範例 A：自動修復 agent 的一次更新

情境 A（虛構）：北辰軟體的建置助理

虛構 北辰軟體是虛構的公司。團隊用一個「建置修復 agent」自動處理 CI 失敗：它讀失敗日誌、查內部知識庫、必要時安裝缺少的套件、重新產生鎖定檔後重跑建置，並把成功的修法記到長期記憶，之後遇到類似錯誤直接套用。架構與文件 ASI05 情境「鎖定檔毒化」及 ASI06 情境同型；以下為虛構，細節停在概念層級。

架構：CI 日誌（不可信）→ agent →｛套件安裝、鎖定檔重新產生、建置、長期記憶寫入｝。

  1. 發生了什麼：某個函式庫發出一個看似正常的小版本更新，裡面藏了惡意程式。agent 在修復建置時，依未固定版本的相依規格重新產生鎖定檔，拉到了這個版本；惡意程式在安裝或匯入時執行，並在 CI 環境中取得機密。同時，agent 把「這次的修法」記進長期記憶，之後遇到類似錯誤，會再度採用同一個版本。
  2. 哪一環出問題：(a) 動態拉取未固定版本的相依，是活的供應鏈（ASI04）；(b) 安裝與匯入時執行了不明程式碼（ASI05）；(c) 把未驗證的成功修法寫進受信任記憶，使污染持續（ASI06）。三者串成一條攻擊鏈。
  3. 對應條目：Agentic Top 10：ASI04、ASI05、ASI06（以及事後擴散時的 ASI08）；T&M：T17、T11、T1。LLM Top 10 2026：LLM04:2026 Supply Chain（2025 版是 LLM03）、LLM10:2026 Improper Output Handling（2025 版 LLM05）、LLM05:2026 Data and Model Poisoning。
  4. 該採什麼控制：
    • ASI04：相依允許清單與版本固定，用雜湊與提交編號鎖定；未簽章或未驗證的套件自動拒絕；分階段發布與雜湊漂移時自動回復；備妥緊急停用開關；
    • ASI05：agent 在受限容器中跑、不以 root 執行、限制對外連線；把「產生」與「執行」分開並加驗證關卡；禁止在正式環境使用 eval；
    • ASI06：禁止 agent 自己的輸出自動寫回受信任記憶；寫入前驗證並附來源；保留快照可回復；未驗證的記憶設有效期；
    • 共通：對 agent 執行環境採零信任，假設 LLM 或 agentic 元件會被利用（文件在 ASI04、ASI08 都有這項）。
  5. 學到什麼：這三條不是三個獨立事件，而是同一次事件的三個階段。若只擋最後一段（例如只掃描惡意程式），記憶裡的壞修法下次還會重演；若只清掉記憶，沒固定版本的相依還是會被拉到新的惡意版本。防線要串起來，且每一環都假設前一環會失守。

3.4 攻擊鏈的視覺化

本章重點與自我檢核

  • ASI04 的核心是「活的供應鏈」：執行期動態載入的元件，需要來源證明、版本固定、緊急停用。
  • ASI05 的結果是主機或容器被入侵，需要主機與執行期專屬的緩解（沙箱、不以 root、禁用 eval、產生與執行分離）。
  • ASI06 是對持久記憶的污染；避免 agent 自己的輸出自動回寫到受信任記憶。
  • 三條常串成一條攻擊鏈；每一環都假設前一環失守。
  • SBOM 只回答「有哪些元件」，不回答「這些元件可能怎麼失效」。
  • 我能解釋「活的供應鏈」與傳統供應鏈的差別。
  • 我能把一個修復 agent 的事故拆成 ASI04、ASI05、ASI06 三個階段並指出切斷點。
  • 我知道 SBOM 是起點而不是結論。
