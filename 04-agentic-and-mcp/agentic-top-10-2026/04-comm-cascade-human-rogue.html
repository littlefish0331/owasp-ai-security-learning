第 4 章　通訊、連鎖、信任與流氓 Agent（ASI07–ASI10）

  • 預估閱讀：約 8 分鐘（不含章末檢核；另有 4 題章末檢核）
  • 對應學習目標：LO4
  • 前置：第 3 章

前三章的主角大多是單一 agent。最後四個條目的舞台是 agent 之間，以及 agent 與人之間：agent 彼此講話時沒人驗證訊息（ASI07）；一個小錯誤在 agent 之間滾成大災難（ASI08）；人太相信 agent，替它的壞決定蓋了章（ASI09）；某個 agent 悄悄偏離了它該做的事（ASI10）。這四條的共同詞是「信任」。

4.2 核心概念：為什麼 ASI09 的緩解不能靠 agent 自己的解釋

ASI09：用人的信任當武器——為什麼不能信「模型寫的理由」

是什麼
agent 因語言流暢、情緒智能與看似專業，容易讓人產生信任（文件稱為擬人化）。攻擊者或失準的設計利用這份信任，影響使用者決策、取得敏感資訊或操縱結果。
為什麼會發生
人容易過度依賴自信、權威的建議，且往往無法獨立驗證 agent 的推理；批准成為習慣。文件點出：agent 成為「無法追蹤的壞影響」，因為最後那個被稽核的動作是人做的，agent 的角色在鑑識中不可見。
怎麼被利用（概念層級）
文件的例子：被污染的供應商發票進入財務 Copilot，Copilot 自信地建議對攻擊者帳戶緊急付款，經理基於信任批准；代理人編造看似合理的稽核理由，讓審查者批准有風險的設定變更；預覽視窗開啟時就觸發有副作用的 webhook，利用使用者「預覽是唯讀」的心智模型（文件稱為同意洗白）。
怎麼防
除了明確確認、日誌與行為偵測，文件有一項很關鍵的設計：提供白話的風險摘要，而不是模型生成的理由。原因是模型的解釋本身就可能是被操縱或編造的。此外要依風險調整自主程度、讓高風險建議視覺上與眾不同、在預覽期間阻擋任何有副作用的呼叫，並對相關人員持續訓練。
常見誤解
「只要要求 agent 解釋理由，人就能把關。」ASI09 的前提正是：被劫持或失準的 agent 會產生令人信服的理由（文件稱為「武器化的可解釋性」）。把關要靠獨立於 agent 的資訊（風險摘要、來源證明、預覽副作用的阻擋）。

4.3 情境範例 B：一個小錯誤如何滾成大事故

情境 B（虛構）：山海航運的自動調度

虛構 山海航運是虛構的公司。調度系統由四個 agent 組成：「分析」agent 評估每日航線風險、「規劃」agent 依分析產生船期調整、「執行」agent 自動下單調整並通知港口、「合規」agent 檢查是否在核定參數內。四者透過內部訊息匯流排互相呼叫，彼此預設互信。與文件 ASI08 的金融交易連鎖情境同型；以下為虛構。

架構：外部氣象與港口通報（不可信）→ 分析 agent → 規劃 agent → 執行 agent →（下單、通知）；合規 agent 事後檢查「是否在參數內」。

  1. 發生了什麼：一則被竄改的港口通報讓分析 agent 把某條航線的風險評分大幅調低。規劃 agent 信任分析的輸出，提高該航線的載量；執行 agent 照單全收並自動下單；合規 agent 檢查後發現「都在核定參數內」，沒有告警。三天後，同樣的錯誤被複製到另外兩條航線，因為分析 agent 把這個評分存進了它的長期記憶。
  2. 哪一環出問題：(a) 起點是被竄改的外部輸入（ASI01 目標被誘導或 ASI06 污染的種子）；(b) agent 之間互信、沒有驗證（ASI07）；(c) 錯誤一路被放大且沒有人在迴路（ASI08，核心）；(d) 合規只檢查「參數內」，看不見整體偏離（缺乏行為基準與偏離偵測）。
  3. 對應條目：起點可歸 ASI06／ASI07，放大階段才歸 ASI08（文件明說：初始缺陷用 ASI04／06／07，只有擴散時才加 ASI08）；T&M：T5、T8；LLM Top 10 2026：LLM01:2026（輸入入口）、LLM03:2026 Excessive Agency、LLM05:2026 Data and Model Poisoning。
  4. 該採什麼控制：
    • 規劃與執行之間加獨立的政策引擎，並對高衝擊動作用政策即程式碼檢查；
    • 爆炸半徑護欄：下單金額與影響航線數量設配額與進度上限，規劃與執行之間加熔斷器；
    • agent 間訊息簽章與雙向認證，並記錄不可竄改的日誌與資料血緣；
    • 行為偏離偵測：觀察「風險評分突然全面降低」「複製到多條航線」這類扇出訊號；
    • 高風險調整需人核准，並用白話風險摘要而非 agent 的解釋（ASI09）。
  5. 學到什麼：ASI08 的特徵是可觀察的症狀：快速扇出、跨範圍擴散、重試震盪、佇列風暴、重複的相同意圖。文件說這些是「清楚的偵測鉤子」。與其追問「誰先錯」，更要先問「這個錯誤為什麼能被放大」。
