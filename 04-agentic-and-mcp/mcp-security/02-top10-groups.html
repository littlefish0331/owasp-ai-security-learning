2.3 核心概念：Tool Poisoning 與 Rug Pull

工具投毒 (Tool Poisoning) 與抽換 (Rug Pull)

是什麼
Tool Poisoning：工具的描述、參數結構或回傳值被埋入針對模型的指示。Rug Pull：工具先以合法面貌通過審查，之後被悄悄換成惡意版本。
為什麼會發生
MCP 工具的描述是寫給模型讀的自然語言，模型把它當作可信的操作說明；而 MCP 的工具定義可以動態載入、缺乏嚴格版本控制，所以審查通過的版本和實際執行的版本可能不同。第 1 章說過：所有伺服器的工具描述都在同一個脈絡裡。
怎麼被利用（概念層級）
官方 MCP03 條目還補充了一件事：投毒不只在描述文字，也可以在結構定義 (schema)：讓一個聽起來無害的操作對映到破壞性動作，且因為「合約本身是惡意的」，表面驗證與稽核紀錄看起來都合法。另一種是「工具遮蔽 (Tool Shadowing)」：一個伺服器的描述去影響模型如何使用另一個可信伺服器的工具。
怎麼防
安裝前：完整檢視（不只看摘要）工具描述與結構；用靜態指標先篩（官方 MCP03 條目列了幾類指標，例如針對模型下命令的語句、提到敏感路徑、動詞加外部目的地的外送模式、隱藏或零寬字元、藏在註解裡的指示）。運行時：以密碼學雜湊固定完整的工具定義（Cheat Sheet 特別強調要雜湊完整定義，包含輸入結構、輸出結構與註記，因為一個被翻轉的唯讀提示就能改變用戶端的核准行為），定義一變就要求重新審查；給每個工具簽章的 manifest；伺服器之間隔離。
常見誤解
「雜湊固定了描述，就沒有 Rug Pull 了。」Cheat Sheet 明說：雜湊只偵測中繼資料的變更，偵測不到定義不變、但伺服器程式碼在背後行為改變的情況；工具註記也只是提示，不是強制。
