5.2 MCP Top 10 的兩個社群建議控制

MCP Top 10 的倉庫另有一個 recommended-controls 資料夾，目前有兩份，都是社群貢獻的可選控制，各自對照到 MCP Top 10 的多個條目。本教材不背書，只說明它們是什麼：

表 5-1　MCP Top 10 的兩個社群建議控制（倉庫 2025/recommended-controls；2026-10-26 讀取）
名稱加入日期是什麼（改寫）自述涵蓋的條目要注意的
Client-Side Tool Risk Gating2026-07-11主機端的控制模式：在模型看到或呼叫工具之前，由 MCP 主機評估每個工具；包含有序風險評分、硬性暴露上限（超過上限的工具不給模型）、定義指紋固定（首次見到時記錄雜湊，之後被悄悄重新定義就進入封鎖並重新審查）、以及人在迴路的逐次呼叫閘門。不需要上游伺服器配合MCP02、MCP03、MCP06、MCP08、MCP09、MCP10文件自述：對 MCP06 只做爆炸半徑限縮，不偵測注入本身；有一個開源參考實作
MCPS（MCP Secure）2026-03-13包在既有 JSON-RPC 訊息外的密碼學安全層（類比 TLS 包 HTTP）：提供 agent 身分、訊息完整性、工具真實性與重放保護自述涵蓋 10 項中的 8 項（MCP01–04、06–09）倉庫文件自述；Cheat Sheet 說明相關的 MCPS Internet-Draft 是「個人提交的進行中工作，不是已採納的 MCP 標準」，並警告別把選配簽章說成一般 MCP 部署的必要條件

這兩個控制屬於 MCP Top 10 專案內的建議，狀態、成熟度與有效性本教材沒有獨立查證；它們也不等於 MCP 規格本身的要求。把它們當作「如果你的威脅模型需要，可以評估」的選項。

5.4 04 階段回顧：四個主題怎麼接起來

本章重點與自我檢核

  • 先分角色：開發 MCP 伺服器看開發指南；使用別人的看第三方使用 Cheat Sheet；兩者都用 MCP Security Cheat Sheet 補最新實務。
  • MCP Top 10 仍是 Beta，只當作共同風險語言；它的兩個建議控制是社群可選，狀態本教材沒有獨立查證。
  • MCP 風險在 Agentic 系列中有明文落點：T16、Playbook 3、ASI02／04／07。
  • 04 階段的脈絡：威脅分類 → Top 10 → 實作指南 → MCP 協定。
  • 給我一個 MCP 情境，我能說出該先看哪一份文件，以及它的成熟度要怎麼引用。
  • 我能說出 MCP 風險在 Agentic 系列的明文落點，並分辨哪些是官方、哪些是作者的整理。
  • 我知道建議控制不是 MCP 規格的要求，也沒被本教材背書。
