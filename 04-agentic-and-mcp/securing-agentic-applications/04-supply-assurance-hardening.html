指南的最後四節回答的是「做完了怎麼知道有效」與「怎麼把它放上線」：供應鏈與探索、驗證（紅隊與行為測試）、部署、執行期強化。本章先看這四節各自給了什麼，再把整個主題收攏到跨文件的位置。

4.1 供應鏈與探索：誰可以被信任

指南第 6 節的重點不是重講一般的軟體供應鏈（它只說「標準供應鏈做法適用」：SCA 掃描、雜湊與套件鎖定、SBOM），而是 agent 特有的三件事。

4.2 驗證：紅隊與行為測試

第 7 節的主張是：agentic 應用的保證策略不能只做靜態測試。它分成兩條線：

  • 紅隊 (7.1)：模擬對手攻擊，範圍涵蓋提示詞注入，但不止於此，還要測試經工具提權、記憶污染與計畫操縱。指南列了數個測試框架與基準（例如 AgentDojo、Agent Security Bench、AgentPoison 等），並指向 ASI 紅隊指南與 GenAI Red Teaming Guide 的附錄。這些是官方列出的範例，不是背書。
  • 行為測試 (7.2)：評估 agent 的活動與互動，而不只是其結構或程式碼，用於找出非預期動作、邏輯錯誤與追求有害目標。方法包括明確的目標定義、基準資料集、在受控環境模擬、人工加自動的評估。選基準時要先分清楚：有些基準測的是一般效能（如準確度），不是安全；基準本身也需要後設評估（不一致、含糊、不完整、不準確）。

指南另外提到「可解釋性稽核」：用思維鏈 (CoT) 看 agent 的推理，但要明白 agent 所說與所「想」不一定一致；在關鍵節點用 HITL；記錄 agent 間的目標協商與工具互動；記錄用了哪些權限集或身分，因為這代表 agent「以為自己在代表誰」。後者與第 1 章的混淆代理人直接相連。

留意第 9 節的口吻和前面不同：它自述是「針對 LLM 驅動或工具增強 agentic 應用的拆解」，內容偏向實務清單，且提到的 AGNTCY 風格能力控制層屬於一種具體的設計；指南沒有把它當成唯一做法。讀的時候把它當作檢查清單的來源，不當成唯一架構。

本章重點與自我檢核

  • 供應鏈：agent 特有的是「執行期產生的程式碼」「不可讓 agent 存取自己的部署」「探索與登錄的信任」。
  • 驗證不能只做靜態測試：紅隊要測提權、記憶污染與計畫操縱；行為測試評估活動與互動；基準本身也要被評估。
  • CoT 不等於 agent 真正的推理；要記錄 agent「以為自己在代表誰」的身分與權限。
  • 部署與執行期強化的核心：角色隔離、閘道仲介工具呼叫、能力限定、完整日誌、非人類身分管理。
  • 本指南的位置：T&M 說威脅、本指南說實作、紅隊指南說驗證；治理另有他處。
