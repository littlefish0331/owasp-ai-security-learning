第 4 章　多 Agent 威脅建模與整合收尾

  • 預估閱讀：約 7 分鐘（不含章末檢核；另有 3 題章末檢核）
  • 對應學習目標：LO4、LO5
  • 前置：第 3 章；威脅建模

前三章讓你有了威脅清單與對策。但清單不會告訴你「我的系統裡每一層各有哪些威脅」。多 Agent 威脅建模指南 (MAS Threat Modeling Guide) 的做法是：用 MAESTRO 七層架構把 T1–T17 放上去，再往外發現清單裡沒有的威脅。本章看這個方法怎麼用，並把整個主題收攏到跨文件的位置。

4.1 這份指南是什麼，跟 T&M 1.1 的關係

它要與 T&M 並用：指南自己說「應與 Agentic AI – Threats and Mitigations 並用」，並強調 agentic 的四個因素會讓威脅更難纏：非決定性、自主性、agent 身分管理、agent 間通訊。

4.2 MAESTRO 七層與 T1–T17

指南用一張表把 T&M 的威脅對到 MAESTRO 的各層。注意：同一項威脅可以出現在多層（例如 T3 同時在第 4、6 層，T13 在第 4、7 層），因為分層的角度是「問題出在哪一層」，不是「這是哪一種攻擊」。

層焦點對應的 T&M 威脅
1 基礎模型LLM 與預訓練模型的完整性、對齊T1（若記憶用於訓練）、T7
2 資料作業向量資料庫完整性、提示管理、檢索攻擊T1、T12

表中 T7 在原文第 1 層列的是「Misaligned & Deceptive Behaviour」；指南的另一張表把同一項寫成「T2 Misaligned & Deceptive Behavior」，是指南內部的筆誤（T2 是 Tool Misuse）。本教材一律用 T&M 1.1 的 T7。

4.3 指南新增的威脅，以及編號衝突

指南的價值在於「往外發現」：用 MAESTRO 逐層問，找出 T&M 清單沒有的威脅。三個案例共新增了 T16 到 T39 的一批編號，例如：「T16 模型不一致導致核准結果不同」（原文 Model Inconsistency Leading to Variable Approvals；同一份報銷單，今天過、明天不過）、「T17 報銷政策嵌入向量的語義漂移」（政策改了但向量資料庫沒更新）、「T22 服務帳號憑證外洩」、「T23 選擇性竄改日誌」、「T24 動態政策強制失效」。

編號衝突：指南的 T16–T39 不是 T&M 1.1 的 T16、T17

T&M 1.1 的 T16 是 Insecure Inter-Agent Protocol Abuse、T17 是 Supply Chain Compromise。但 MAS 指南（2025-04，早於 T&M 1.1 的 2025-12）在其案例裡把 T16、T17 用在別的威脅上（如上），且 T18 以後也是指南自己的編號。引用 T16 以上的編號時，一定要同時寫出名稱與出處，例如「MAS 指南 T16 Model Inconsistency」或「T&M 1.1 T16 Insecure Inter-Agent Protocol Abuse」。

連指南自己的案例之間編號也不一致：同一項「服務帳號憑證外洩」（Service Account Exposure，也可說成服務帳號外洩），在 RPA 案例編為 T22，在 Eliza OS 案例編為 T21；「選擇性竄改日誌」則分別是 T23 與 T22。所以對 T16 以上的編號，名稱比編號可靠。

編號重疊是事實（作者逐一核對了兩份 PDF）；為什麼會重疊，官方沒有說明。作者的推測是：MAS 指南寫成時，T&M 的編號還只到 T15（2025-03-06 的 Navigator 速查圖只列了 15 項，與此一致），T&M 後來才加入 T16、T17，兩邊便撞號。作者整理，非官方：本教材沒有讀過 T&M 早期版本的完整內容來證實這件事。

4.4 用 MAESTRO 做一次威脅建模：流程

指南的三個案例各說明一件事：RPA 報銷 agent 示範「T&M 基準威脅 + MAESTRO 延伸威脅」；Eliza OS（一個與區塊鏈互動的 agent 框架）示範框架與外掛帶來的威脅；Anthropic 的 MCP 協定示範「協定本身」該怎麼建模，並直接預告了下一個階段的主題：第 4 主題 MCP 安全。

本章重點與自我檢核

  • MAS 指南（v1.0，2025-04-22 封面／2025-04-23 資源頁）不另立分類，而是用 MAESTRO 七層把 T&M 的威脅放進架構、再往外找新威脅。
  • 同一項威脅可出現在多層；分層是「問題出在哪」，不是「攻擊種類」。
  • 指南新增的 T16–T39 與 T&M 1.1 的 T16、T17 編號衝突，指南各案例之間編號也不完全一致；引用要同時寫名稱與出處。
  • agentic 的四個因素讓威脅更難纏：非決定性、自主性、身分管理、agent 間通訊。
  • 這個主題是後三個主題（Agentic Top 10、Securing Agentic Applications、MCP）共同的地基。
  • 我能把一個多 agent 系統的元件對應到 MAESTRO 七層，並說出每層可以先檢查哪些 T 編號。
  • 我知道 T16 在兩份文件裡指不同的東西，引用時會同時寫名稱與出處。
  • 我知道 MAS 指南的角色是方法示範，不是第二套分類。
