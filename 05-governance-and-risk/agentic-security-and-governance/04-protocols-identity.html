第 4 章　協定、Agent 身分與供應鏈

  • 預估閱讀：約 8 分鐘（不含章末檢核；另有 4 題章末檢核）
  • 對應學習目標：LO4
  • 前置：第 3 章

上一章結論是：權限面是兩種失效共同的根因。這一章看三條把「權限」變成可治理對象的線：協定（agent 怎麼被授權去呼叫東西）、身分（誰在行動）、供應鏈（行動的元件從哪來）。報告都用同一句話收尾：這些主要是架構與治理問題，不是單點的程式錯誤。

4.1 三類協定與它們的治理問題

報告把 agent 協定分成三類，說它們「已構成多數正式環境 agentic 系統的骨幹」，也說「協定治理沒有跟上採用」。下表整理各類的代表協定與報告標示的採用程度（截至 2026 年）：

報告列了跨類別的重複弱點：身分在複合與傳遞信任中被稀釋、能力暴露過多、跨廠商的稽核軌跡破碎、圍堵與撤銷機制弱、對自主委派的能見度有限，並說這些因「廠商與部署組織之間的共同責任模型破碎」而加劇。

報告給的「2026 年最低期望」

部署標準化 agent 協定的組織，至少要能證明：agent 與工具有可密碼學驗證的身分；對委派與自主有明確限制，含升級路徑與人類介入的觸發點；對共享脈絡與描述的驗證與清洗；最小權限的執行環境；協定伺服器與轉接器的供應鏈控制（來源、簽章、弱點管理）；稽核等級的協定層遙測；快速撤銷與圍堵。報告說：缺少這些基礎，採用協定的結果「一貫是風險放大的速度快過治理結構的反應」。

4.2 NHI 與 Agent 身分：兩層，不是同義詞

為什麼報告堅持把兩者分開

是什麼
非人類身分 (Non-Human Identity, NHI) 是非人類實體的數位表示與認證：傳統上是靜態的服務帳號與 API 金鑰。Agent 身分是動態的密碼學框架，用來證明 agent 的身分並治理有獨立推理與跨邊界執行能力的自主 agent。報告說前者是「認證原語」，後者是「建立在它之上的治理框架」。
為什麼會出問題
傳統 NHI 在認證當下回答一個問題：「這個實體可以進來嗎？」答案成立到有人輪替憑證為止，這對每次做同樣事的工作負載可行。對 agent 不行：agent 會推理、會委派給其他 agent、會在執行期發現新工具，問題變成「是誰委派了這個 agent、它現在想做什麼、還被允許嗎」。報告的一句話：NHI 告訴你憑證有效，卻無法告訴你持有它的推理實體是否該做它現在做的事。
怎麼被利用（概念層級）
報告列了弱身分策略的風險：身分偽冒（多個 agent 共用一個 NHI 會毀掉當責）、幽靈 agent（為任務啟動卻未下線、仍有有效身分的 agent，成為休眠後門）、信任傳遞失效（A 信任 B，B 委派給不受信任的 C）、第三方供應鏈（外部技能或外掛以呼叫流程的權限執行被污染的資料）、憑證蔓延、遺留 NHI 與人類代理身分（agent 共用服務帳號或人類身分而繼承不當權限）。報告也強調「憑證範圍就是爆炸半徑」：憑證範圍過大，不論起因是對抗性或自主，傷害都會發生。
怎麼防
報告要求把身分視為密碼學斷言，而非一個簡單的憑證：身分證明（發 token 前驗證 agent 的程式碼完整性、模型權重與執行環境）、可驗證憑證（短效，而非長效 API 金鑰）、身分串接（讓 token 綁定發起的主體，防混淆代理人，使用 Token Exchange 保留脈絡）、動態存取（只給目前推理步驟需要的權限，即時授予與縮減）、agent 命名服務（登錄與發現非人類身分）、憑證蔓延管理。另外要求自動化的身分生命週期（短效、隨工作流結束而下線）與以程式碼定義的權限政策 (policy-as-code)。
常見誤解
「我們已有 NHI 治理（秘密管理、輪替），所以 agent 身分沒問題。」報告的立場是這不夠：輪替與憑證管理處理的是「憑證有效嗎」，沒處理「持有者現在該不該做這件事」。

報告把弱身分風險對映到 OWASP 的 Non-Human Identities Top 10（2025 版）：例如幽靈 agent 對應 NHI1 不當下線與 NHI7 長效秘密；信任傳遞失效對應 NHI5 權限過大與 NHI9 NHI 重用。這些對應是報告自己寫的，NHI Top 10 本身不在本教材範圍。

作者整理，非官方：「身分是新的邊界」和你熟悉的概念

如果你熟悉雲端 IAM，這一節的主軸是：從「在登入時檢查一次」變成「在每個動作時檢查」。類比是「長效的 API 金鑰」對「每次請求簽發的短效 token 加上政策引擎」。這個類比是作者的說明，報告沒有用這個說法，也沒有說要採某個特定產品。

4.3 供應鏈：從「裝了什麼」到「能組合出什麼」

報告對 AI 物料清單 (AIBOM) 的論述有一個關鍵轉折。傳統 SBOM 記錄「裝了什麼元件」。但 agent 可以在執行期動態發現、挑選並呼叫外部能力，包含技能、工具、外掛、登錄庫、檢索來源與被委派的子 agent，因此有效的相依圖是在執行期才建起來的。報告的結論：供應鏈安全除了問「有什麼元件」，還要問「執行期能組合出什麼能力、是在誰的權限下執行」；來源證明要從靜態的元件清冊，延伸到簽章、完整性驗證與執行期證明。

5高影響流程要求決策層級的可追溯性能重建哪些元件、工具與被委派的 agent 對結果有貢獻

報告還有一章談可解釋性，結論偏務實：傳統的特徵歸因方法不適用於 agent，需要的是「軌跡層級的透明度」，也就是結構化的追蹤紀錄，包含簡明的人類可讀理由、連結的執行證據（工具輸入輸出、檢索來源、狀態變化）與診斷訊號。它提醒思維鏈 (chain-of-thought) 的「解釋」不保證忠實於實際決策，這與 ASI09（人機信任利用）有關：agent 可能用無法獨立驗證的解釋說服人類核准不安全的動作；也說現有的觀測、記錄與追蹤工具，經常是支撐解釋與稽核的實際機制。

本章重點與自我檢核

  • 三類協定：到工具（MCP）、agent 之間（A2A、ACP）、發現（NANDA、ANS）；各有偽冒、投毒、信任傳遞等風險，共同的弱點是身分稀釋與稽核破碎。
  • NHI 是認證原語；Agent 身分是建在其上的治理框架。NHI 說憑證有效，Agent 身分要說持有者此刻該不該這樣做。
  • 防護方向：身分證明、短效可驗證憑證、身分串接、動態存取、命名服務、自動化生命週期、policy-as-code。
  • 供應鏈從「裝了什麼」到「執行期能組合什麼、在誰的權限下」；高影響流程要決策層級的可追溯性。
