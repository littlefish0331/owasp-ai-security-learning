第 2 章　Agent 分類與 2025–2026 威脅

  • 預估閱讀：約 8 分鐘（不含章末檢核；另有 4 題章末檢核）
  • 對應學習目標：LO2
  • 前置：第 1 章

「我們有幾個 agent？」這個問題很難回答，因為「agent」可以是員工桌面上的個人助理、CI 流程裡的程式碼審查機器人、也可以是低程式碼平台上業務人員拉出來的自動化流程。報告的第一個貢獻，就是給你一套把它們分開來看的方法；第二個貢獻，是說明 2025–2026 年的攻擊大多走哪兩條路。

2.1 三個獨立維度與一個貫穿維度

報告把 agent 分類拆成三個彼此獨立的維度，並說「任何類型的 agent 都可以用任何實作方式建置、參與任何組合模式」。這很重要：它避免你把「它是程式碼 agent」誤當成「所以我知道它怎麼被建、怎麼被編排」。

表 2-1　三個維度與治理意義（報告 Agents Taxonomy，改寫）
維度它回答什麼分類治理上最影響什麼
類型
(Agent Type)		它做什麼、在哪裡運作五類：企業內部 (Enterprise)、程式碼 (Coding)、面向客戶 (Client-Facing)、個人 (Personal)、基礎設施／營運 (Infrastructure / Ops)信任邊界、適用的法規、主要治理挑戰
實作
(Implementation Pattern)		它是怎麼被建出來的完整編排框架、輕量函式庫組合、平台原生／低程式碼稽核面與組織能見度：你能不能盤點、能不能監控
組合
(Composition Pattern)		agent 彼此怎麼安排單一 agent 加工具、多 agent 系統、分散式 agent 鏈、agent 生成架構信任邊界結構與連鎖失效風險

(Autonomy，貫穿)		沒有人確認它能自己做什麼受監督、半自主、完全自主人類偵測與介入的時間窗

五個類型各有最突出的治理挑戰（報告原表）：企業 agent 是「權限與脈絡不一致」，程式碼 agent 是「自主程度超過圍堵能力」，面向客戶的 agent 是「對抗性暴露加法規負擔」，個人 agent 是「超出企業治理的能見度缺口」，基礎設施 agent 是「爆炸半徑」。

實作維度的關鍵警告

報告說：不要以為採用框架就等於有能見度。完整編排框架提供追蹤與一些內建的安全掛鉤點；輕量函式庫組合的安全特性「完全由建置者決定」，除非刻意加入，否則沒有標準的掛鉤、遙測或稽核點；平台原生與低程式碼則「治理完全取決於平台能力」，建置者最不容易理解繼承來的風險，是影子 AI 風險最高的一類。

2.2 自主程度：真正的問題是「沒有人確認時它能做什麼」

自主程度為什麼是貫穿維度

是什麼
三個等級：受監督（人類核准每個動作，agent 只建議）、半自主（agent 執行例行動作，人類審查被標記的項目）、完全自主（agent 自己規劃、執行並反覆迭代）。
為什麼重要
報告的說法是：自主程度升高，風險變大「不是因為威脅格局改變，而是因為人類偵測與介入的時間窗變窄」。同一個程式碼 agent，受監督與完全自主的風險完全不同。
治理含義
受監督：標準應用程式安全控制即可。半自主：需要依風險分級的審查，且監控必須抓得到人沒審的部分。完全自主：需要確定性的強制機制（掛鉤、熔斷器 (Circuit Breaker)）、持續的行為監控與停止開關。另外有兩項額外要求：對執行時間、API 呼叫與運算成本設預算上限，以圍堵失控的自主迴圈；並把它當成高風險主體納入身分管理，擁有專屬的 agent 身分、明確的權限邊界與和部署它的人分開的稽核紀錄。
怎麼用
盤點每一個 agent 時，問兩題而非一題：它是什麼類型？它沒有人確認時能做什麼？
常見誤解
「自主程度高的 agent 才危險。」報告觀察到：資安公告數量與採用程度相關，而不是與自主程度相關。公告最多的專案都是半自主框架或程式碼 agent，因為它們被廣泛部署且是高價值目標（報告同時提醒這部分是通報偏差：社群大就多人通報）。

2.3 兩條主要路徑：提示詞注入與供應鏈

報告把 2025–2026 的威脅格局歸納為六個面向：自主程度擴張、提示詞注入、agent 供應鏈、影子 AI 與 vibe coding、agent 身分、以及分層攻擊面模型。其中兩條是「幾乎所有事故都走過」的路徑。

路徑一：提示詞注入。報告稱它是 agentic 攻擊的「主要傳遞機制」。一個在單純模型上只改變一則回覆的注入，在 agent 上可以改寫目標、破壞多步驟計畫、偽造 agent 間訊息，並連鎖成跨系統的工具動作；這也是它對映到 ASI 十個類別中的六個的原因。報告的說法是這是架構問題：LLM 把資料平面與控制平面塞進同一個通道，沒有可靠的機制在系統提示詞、使用者請求與外部取得的內容之間強制權限邊界。因此實務者的方向已經改變：從試圖阻止注入，轉為限制被注入的 agent 能做什麼。你在 AI Exchange 第 4 章 看過的縱深防禦，就是這個方向。

為了討論「限制能做什麼」，報告引用兩個設計框架，並指出它們的限制：

  • 致命三要素（Simon Willison 提出）：agent 同時具備「存取私有資料」「暴露於不受信任的內容」「能對外溝通」三個性質時，單一注入就能走完整條攻擊鏈。
  • Agents Rule of Two（Meta，2025 年 10 月）：在不需要人類核准的對話中，agent 至多滿足這三個性質中的兩個；三個都滿足時，要有人類核准才能行動。
  • 報告的保留：Rule of Two「適合用來說明結構性問題，但不是完整防線」；它引用的行事曆邀請攻擊，在只滿足兩個性質時仍然可行。

路徑二：agent 供應鏈。報告稱它在 2025–2026 成為「agentic 生態中演變最快的攻擊途徑」，攻擊者瞄準每一層：協定基礎設施、技能登錄庫與核心 AI 套件。它指出一個傳統供應鏈沒有的攻擊面：「工具投毒」，也就是惡意指令藏在工具描述欄位中，人類審查看不到，但 AI 模型把它當作可信脈絡處理；payload 不在程式碼裡，而在元資料裡。相關手法還有「描述在核准後被更改」與「惡意伺服器遮蔽可信伺服器的工具」。報告歸納的共同模式是：攻擊者瞄準 agent 隱含信任的元件，爆炸半徑隨相依圖放大。

作者整理，非官方：為什麼這兩條路徑有共同點

兩條路徑看似不同（一個是輸入，一個是元件），但報告用「AI Agent Traps」框架把它們串起來：攻擊者的目標不是 agent，而是 agent 所消費的資訊環境，包括工具描述、檢索語料、持久記憶、技能登錄庫與網頁內容。本教材把這整理成：提示詞注入與供應鏈投毒，是同一件事的兩種進入點，就是讓 agent 信任了不該信任的東西。這是作者對報告論述的簡化，報告本身沒有這樣兩句話概括。

本章重點與自我檢核

  • 分類有三個獨立維度（類型、實作、組合）加貫穿的自主程度；任何類型可搭配任何實作與組合。
  • 採用框架不等於有能見度；低程式碼與平台原生的影子 AI 風險最高。
  • 自主程度升高是因為偵測與介入的時間窗變窄；完全自主需要確定性強制、行為監控與停止開關。
  • 提示詞注入是架構問題；實務方向是限制被注入的 agent 能做什麼。致命三要素與 Rule of Two 有用但不是完整防線。
  • 供應鏈的新攻擊面是工具描述等元資料（工具投毒）。
  • 一個事件可對映多個 ASI 條目；教材的事件表只轉述報告。
  • 我能用三個維度加自主程度描述一個 agent。
  • 我能解釋為什麼「採用框架就有能見度」是誤解。
  • 我知道報告對 Rule of Two 的保留。
