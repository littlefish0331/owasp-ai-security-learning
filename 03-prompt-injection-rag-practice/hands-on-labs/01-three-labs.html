讀完條目與 Cheat Sheet，下一步常是「親手看一次」。OWASP 的 AI 資源裡有三個專案專為此設計。這一章把它們並排：各是什麼、授權、版本、用哪一版 Top 10 的編號；再談一個比「選哪個」更重要的問題：怎麼安全地執行一個故意有洞的程式。

1.1 什麼是刻意有漏洞的應用

刻意有漏洞的應用 (Intentionally Vulnerable Application) 是為了教學，故意放入可被利用弱點的程式。在 LLM 領域，它們常以奪旗賽 (Capture The Flag, CTF) 的形式出現：給你一個目標，達成就得到旗標。三個專案的自述 官方（這裡的「官方」指專案自己的說明）：PromptMe 是含 10 個受 LLM Top 10 啟發的實作挑戰；PwnzzAI 是以 pizza shop 為情境的 Flask 應用，每項弱點附示範、利用情境與加固替代方案 (Hardened Alternative)；FinBot CTF 被官方資源頁稱為「Juice Shop for Agentic AI」，屬於 GenAI Security Project 的 Agentic Security Initiative。

未能確認：本教材沒有執行過這三個專案

本教材只讀了 README、專案頁與官方說明，沒有安裝或執行，所以不評價挑戰的品質與難度。後面講的是怎麼選、怎麼安全地用、怎麼接回防禦，不是操作教學。

1.5 核心概念：安全地執行刻意有漏洞的應用

這個應用本身就是不可信的

是什麼
專案為了教學，故意在程式裡留下可被利用的弱點，而且是會真的呼叫模型、有時還帶資料庫或工具的完整應用。三個專案都自己警告了這一點 官方：PromptMe 說它使用不安全的程式碼與套件，強烈建議在虛擬或沙箱 (Sandbox) 環境中執行；PwnzzAI 標示僅供教育、請勿用於正式環境。
為什麼要特別處理
弱點是你預期的，但弱點的後果不會因為是練習而縮小。應用若連到網路、持有可計費的金鑰、或放了真實資料，後果就是真的。換成前置觀念的說法：這個應用本身位在你的信任邊界之外，不該拿到任何你不想失去的東西。作者整理，非官方
沒做到會怎樣（概念層級）
四種後果：暴露（有洞的服務被不相干的人使用）；金鑰（金鑰放在應用讀得到的地方，應用被攻破就外洩）；費用（計費金鑰沒有上限，LLM06:2026 Unbounded Consumption 談的就是這種成本不對稱）；資料（真實資料送進有洞的應用，或送給雲端模型）。
怎麼做 作者整理，非官方
  • 在虛擬機或容器網路內執行，不接公司內網；只綁本機位址，不對外開放連接埠。
  • 專為練習申請金鑰，設定用量與費用上限，用完撤銷；不要使用正式金鑰。
  • 只用虛構的資料，不匯入真實客戶或員工資料。
  • 練習結束就銷毀環境。
  • 攻擊技巧只用在你自己架設的練習環境；對任何其他系統測試，都需要事先取得授權。
常見誤解
「這是 OWASP 的專案，所以裝在哪裡都安全。」專案的出處不會改變它「刻意有洞」的事實；OWASP 專案頁與 README 本身就在警告這一點。

情境 E（虛構）：青禾金融的共用測試機

虛構 青禾金融是虛構的公司。同事把 FinBot CTF 用 Docker Compose 部署在一台可從網際網路連到的測試主機上，在設定檔放入團隊共用的正式 LLM 金鑰，並開放連接埠，方便大家在家一起練習。

架構：網際網路 → 測試主機（開放連接埠）→ 刻意有漏洞的 FinBot → 設定檔內的正式金鑰 → 計費的模型服務。

  1. 發生了什麼：數天後，金鑰的用量帳單遠高於預期，主機上也出現來源不明的連線紀錄。（概念層級，不描述利用手法。）
  2. 哪一環出問題：(1) 暴露：預期會被攻破的應用放在可上網的位置；(2) 金鑰：正式金鑰放在這個應用的設定裡；(3) 費用：金鑰沒有用量上限。三者疊加。
  3. 對應條目：費用面向對應 LLM06:2026 Unbounded Consumption；其餘是通用資安原則（最小權限 (Least Privilege)、信任邊界）。作者整理，非官方
  4. 該採什麼控制：移到隔離網段或本機虛擬機且不對外；撤銷已放進設定檔的正式金鑰，改用專為練習申請、有上限的金鑰；多人同玩就各自在自己的隔離環境執行。
