1.1 核心概念：RAG 不減少風險，而是重新分配風險

風險重新分配

是什麼
RAG Security Cheat Sheet 開宗明義地說，RAG 把模型的回答建立在檢索到的文件上，能減少幻覺、帶入領域知識，但它不是降低風險，而是把風險散布到整條資料管線：從攝入 (Ingestion)、嵌入生成、儲存、檢索、生成，到輸出與下游整合，每一站都有新的攻擊面。官方
為什麼會發生
聊天機器人的輸入只有使用者的問題；RAG 另外多了一條由「語料與索引」決定的輸入。語料裡的每份文件、每個區塊 (Chunk) 的嵌入、向量資料庫 (Vector Database) 的索引，都成為攻擊者可以影響、而使用者與維運者不容易看見的資產。這在 AI Exchange 第 6 章稱為「第二個、幾乎看不見的輸入通道」。
怎麼被利用（概念層級）
LLM09:2026 用四句話歸納向量與嵌入層的失敗方式：投毒讓系統答錯、反推讓它洩漏、干擾讓它沉默、存取控制失效讓它不分對象。其中「干擾」指檢索干擾 (Retrieval Jamming)：放入一份專為特定查詢被取回、並讓模型拒答或宣稱沒有資料的「阻擋文件」，文件本身不帶任何惡意指令，是對檢索層的可用性攻擊。這四句話的共通點是：許多攻擊在檢索的內容完全沒有惡意指令時也會成功，因為它們利用的是嵌入空間的幾何與相似度搜尋的機制，而不是模型遵循指令的行為。官方
怎麼防
沒有單一控制。Cheat Sheet 的做法是沿著管線，在每個階段各放一組控制，並要求任何一站失效時都不要退回不安全狀態（見 Section 14）。LLM09:2026 的緩解則依六類組織：權限與存取控制、資料驗證與來源驗證、依信任層級分隔資料、異常偵測、儲存生命週期、監控與事件應變。
常見誤解
「文件本身是乾淨的，所以向量庫也安全。」LLM09:2026 與 Cheat Sheet 都不同意：嵌入可以被操弄到靠近目標查詢，也可以被反推回原文，所以向量庫要與來源文件適用同等級的存取控制與保護。

1.2 14 個 Section 的地圖與實作優先序

Cheat Sheet 一開始就把控制分成三個優先層級：立即實作（基礎）、接著實作（合規與稽核）、進階（高安全與受管制環境）。下表把 14 個 Section 與優先層級對在一起；「管線位置」與「寫入端／讀取端／生成端」的歸類，是作者為了幫你記憶加上的分組。

表中列的順序是作者依「三端」重排的，不是 Cheat Sheet 的編號順序。看這張表可以得到兩個觀察：

  • 「立即」層級幾乎都是邊界類控制：誰能寫進來（見 Section 1）、誰能讀出去（見 Section 4、6）、輸出出去前驗證（見 Section 9）、出事時看得到（見 Section 12）、失效時不退回不安全狀態（見 Section 14）。作者整理，非官方
  • 需要較多專業的偵測類控制被放在「進階」：嵌入分布監控、跨模型驗證與差分隱私式的噪聲，只建議高安全或受管制環境採用。

1.3 LLM09:2026 管到哪裡為止

RAG 的問題常橫跨好幾個 LLM Top 10 條目。LLM09:2026 自己寫明了它與其他條目的邊界，下表把官方寫明的邊界整理出來。

表 1-2　LLM09:2026 與相鄰條目的邊界（官方明載；最後一欄的「怎麼讀」為作者整理）
相鄰條目官方劃給它的範圍怎麼讀
（作者整理）
LLM01:2026
Prompt Injection		經由檢索內容的間接提示詞注入惡意指令藏在被取回的文字裡 → 看 LLM01:2026；攻擊靠嵌入空間的位置才取回得到 → 看 LLM09:2026
LLM05:2026
Data and Model Poisoning		嵌入模型在訓練階段被投毒改的是模型本身 → LLM05:2026；改的是語料或索引 → LLM09:2026
LLM04:2026
Supply Chain		向量庫函式庫的序列化缺陷弱點在第三方軟體套件 → LLM04:2026
ASI06:2026
Memory and Context Poisoning		不依賴嵌入幾何的 agent 記憶攻擊agent 記憶被寫入惡意內容，但取回機制不靠相似度 → ASI06:2026

官方另外指出：只用 BM25 之類關鍵字檢索、或讓 LLM 直接走訪文件樹的「無向量」檢索系統，仍然繼承所有非幾何性質的風險，但沒有 LLM09:2026 的攻擊面。意思是：LLM09:2026 的核心是「相似度搜尋位於資料來源與提示詞之間」這件事。

作者整理，非官方：Cheat Sheet 與 AI Exchange 的涵蓋關係

Cheat Sheet 開頭寫「沒有任何現有的 OWASP 指引全面涵蓋這個攻擊面」，而 AI Exchange 已有 RAG 概觀（教材 AI Exchange 第 6 章）。作者的讀法是：兩者寫作時間與焦點不同，AI Exchange 偏威脅建模與跨文件的控制地圖，Cheat Sheet 偏可實作的做法，所以彼此是互補的，不是矛盾。這是作者的解讀，官方沒有說明兩者的關係。AI Exchange 是否把 RAG 風險對照到 LLM09:2026 未能確認（見參考資料頁），本教材不宣稱有或沒有。

1.4 驗證標準的位置：AISVS C8

Cheat Sheet 提到，AISVS 在 C08「記憶、嵌入與向量資料庫」一章以驗證標準層級處理 RAG，Cheat Sheet 則提供「可在生產環境落實的做法」。LLM Top 10 2026 的附錄把 LLM09:2026 對應到 AISVS 的 C5（存取控制與身分）與 C8 為主要防線，C1、C7、C12 為支持。附錄也聲明：這是章節粒度的方向性指引，不是合規對照。官方

用你熟悉的類比：LLM09:2026 是「風險是什麼」，Cheat Sheet 是「怎麼做」，AISVS C8 是「做到了怎麼驗證」。這個三層對應是作者的記憶輔助，不是官方的說法。作者整理，非官方

本章重點與自我檢核

  • RAG 不減少風險，而是把風險散布到整條管線；許多向量層攻擊在內容沒有任何惡意指令時也成立。
  • LLM09:2026 的四句框架：投毒讓系統答錯、反推讓它洩漏、干擾讓它沉默、存取控制失效讓它不分對象。
  • Cheat Sheet 的 14 個 Section 有三個優先層級；「立即」層級以邊界類控制為主。
  • LLM09:2026 的邊界：經檢索的指令注入屬 LLM01:2026；訓練期投毒屬 LLM05:2026；函式庫缺陷屬 LLM04:2026；不靠嵌入幾何的 agent 記憶攻擊屬 ASI06:2026。
  • 我能說出 LLM09:2026 的四句框架，並各舉一個例子。
  • 我能為一個 RAG 專案挑出「立即」層級該先做的控制。
  • 我能判斷一個 RAG 事件該優先查 LLM01:2026、LLM04:2026、LLM05:2026、LLM09:2026 還是 ASI06:2026 的哪一個。
