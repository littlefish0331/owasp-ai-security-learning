第 2 章　寫入端：文件投毒、嵌入操弄與攝入供應鏈

  • 預估閱讀：約 9 分鐘（不含章末檢核；另有 3 題章末檢核）
  • 對應學習目標：LO2
  • 前置：第 1 章；AI Exchange 第 6 章表 6-1（語料投毒、索引遭竄改）

寫入端回答一個問題：誰能影響進入語料與索引的東西？Cheat Sheet 把這件事拆成三組控制：文件本身（見 Section 1）、文件變成的嵌入（見 Section 2）、以及把文件送進來的連接器（見 Section 13）。這一章的重點是看懂一個容易誤會的地方：雜湊 (hash) 相符，只代表文件沒變，不代表文件安全。

2.1 文件投毒 (Document Poisoning)

Cheat Sheet 稱文件投毒是「最常見、最容易被利用的 RAG 攻擊向量」，凡是多人或多系統可以上傳文件的共享知識庫（例如 Confluence、SharePoint、雲端硬碟、物件儲存）都有風險。官方 它列出的入口是：

  • 攻擊者把含有隱藏指示的文件上傳到共享知識庫；
  • 被入侵的資料來源把投毒文件送進攝入 (Ingestion) 管線；
  • 內部人員修改既有文件，加入在一般畫面看不見、但抽取出的文字裡存在的對抗性內容；
  • 以不可見的 Unicode 字元（例如零寬空格）編碼隱藏指示，人眼看不到，模型卻會處理。

這個威脅在 AI Exchange 第 6 章叫「檢索語料投毒」。Cheat Sheet 的做法是下面五類控制，而且它特別強調：防篡改要靠「分開保管的基準」，而不是單靠雜湊。

2.2 「雜湊相符」與「內容安全」是兩件事

2026-10-04 的修訂（保護文件完整性基準免遭竄改）讓 Cheat Sheet 把這個區別寫得很清楚。官方 用你熟悉的軟體發佈類比：你下載一個安裝檔並比對簽章，簽章相符只證明「這是發佈者簽的那份」，沒有證明「發佈者簽的那份沒有惡意」。

核准當下的內容是否含提示詞注入不能。官方明說：相符「只建立與核准基準的一致性，不證明內容安全或沒有提示詞注入」攝入時的掃描、來源允許清單、人工審核

所以「雜湊相符」是個必要但不充分的檢查：它關閉「核准後被偷偷改動」這條路，但「核准時就已含有惡意內容」這條路要靠來源與內容審查關閉。

2.3 嵌入操弄 (Embedding Manipulation)

嵌入是文字的數值表示，用於相似度搜尋。Cheat Sheet 描述的威脅是：對抗性輸入可以被製作成「嵌入很像某些目標查詢」，於是即使內容與查詢毫不相關，也會被取回。它也明說這是進階攻擊，需要知道所用的嵌入模型，與高安全環境最相關。官方

這跟文件投毒的差別在於攻擊者利用的是「嵌入空間的位置」：LLM09:2026 說得更直接，即使取回的內容沒有任何惡意指令，這類攻擊仍可能成立。它還點出成功需要兩個條件同時成立：投毒內容必須被取回（幾何條件），而且必須影響回答（生成條件）；防守者可以在任一層介入。官方

防禦的重點不是「讀懂每份文件的嵌入」，而是用外部可觀察的統計來發現不自然的接近程度：嵌入分布、漂移、多模型交叉比對、版本記錄。這些控制偏專業，所以 Cheat Sheet 放在「進階」。

未能確認：LLM09:2026 轉述的研究數字與 CVE

LLM09:2026 引用了許多研究成果與漏洞編號（例如嵌入反推的重建比例、少量投毒文件即可達到高成功率的結果、兩個向量資料庫 (Vector Database) 與 RAG 引擎的 CVE）。這些是 OWASP 文件的轉述，本教材沒有獨立回到原論文或 CVE 資料庫核對，因此後面章節只在需要時以「依 OWASP 文件轉述」引用，不自行引用其他統計。

2.4 攝入連接器也是供應鏈

RAG 的攝入常依賴第三方連接器：雲端硬碟、協作平台、通訊軟體、物件儲存或網頁爬蟲。Cheat Sheet Section 13 的立場很簡單：連接器是供應鏈的一部分，要用處理供應鏈的方式處理。官方 這與你在應用程式相依套件上用過的做法一致，只是對象變成資料管線：

  • 不隱性信任外部整合：被入侵的雲端硬碟連接器可以把投毒文件注入語料。
  • 不要自動同步外部來源後直接可用；在攝入與進入向量庫之間加上暫存或審核。
  • 連接器只給「讀取特定資料夾」的權限，不給整個雲端硬碟的管理權。
  • 固定嵌入模型與攝入函式庫版本：沒有控管的嵌入模型更新，會改變整個語料的檢索行為。

2.5 情境範例 C：每晚同步的內部知識庫

情境 C（虛構）：海灣物流的營運知識助理

虛構 海灣物流是虛構的公司。他們建了一個營運知識助理：每晚由第三方連接器從共享雲端硬碟與一個合作夥伴的文件入口抓取檔案，自動嵌入並寫入向量庫，白天給客服與調度員查詢。共享雲端硬碟的多個資料夾，合作夥伴與外包人員都有編輯權。

架構：共享雲端硬碟／夥伴入口 → 第三方連接器（管理員權限）→ 夜間自動嵌入 → 向量庫（應用程式服務帳號可直接寫入）→ 檢索 → LLM → 調度員介面。

  1. 發生了什麼：某天，助理對一個常見的運費查詢，給出了一段看似權威、但與公司政策不符的規則；稽核發現這段規則來自一份最近被編輯的文件，編輯者是一個外包帳號。該文件被編輯後，沒有任何人收到通知，隔夜就被嵌入並可被檢索。
  2. 哪一環出問題：(1) 來源：外包與夥伴對資料夾有寫入權，沒有來源允許清單，也沒有核准流程；(2) 連接器：用管理員權限、自動同步、攝入與可用之間沒有暫存與審核；(3) 完整性：沒有以簽章保護的核准基準，所以事後也無法證明這份文件何時、被誰改了什麼；(4) 向量庫：服務帳號可直接寫入，沒有索引修改記錄。
  3. 對應條目：Cheat Sheet Section 1（文件投毒）、Section 13（攝入的供應鏈風險）、Section 7（索引完整性）；LLM09:2026 的檢索期資料投毒（寫入語料後透過檢索進入提示詞）；若該文件另含給模型的指令，則同時涉及 LLM01:2026。
  4. 該採什麼控制：
    • 來源允許清單與新來源核准流程；高風險資料夾的修改要有審核；
    • 連接器改為只讀特定資料夾，同步後先進暫存區，掃描與審核通過才可檢索；
    • 對核准文件建立簽章過的摘要清單，基準更新要另行授權；
    • 向量庫的寫入權限限於攝入管線，所有索引修改記錄身分與時間，並對索引大小的異常變化發出警示。

注意這個情境不需要任何精巧的嵌入技巧。只靠「誰有寫入權」的管控缺口，內容就能進到答案。這也是 Cheat Sheet 把來源與完整性放在「立即」層級的理由（作者整理）。

本章重點與自我檢核

  • 寫入端的核心問題：誰能影響進入語料與索引的東西。
  • 完整性清單要與文件庫分開保管、以簽章或 MAC 保護；摘要相符只證明「沒被改過」，不證明內容安全。
  • 基準更新要與一般文件寫入分開審查授權。
  • 嵌入操弄是進階威脅，防禦靠分布監控、漂移偵測與跨模型比對，Cheat Sheet 放在「進階」層級。
  • 攝入連接器是供應鏈：最小權限、暫存審核、固定版本、維護清冊。
  • 我能說明為什麼摘要相符不等於內容安全。
  • 我能為一條攝入管線標出至少三個檢查點，並說明失敗時該怎麼處理。
  • 我能區分「來源允許清單」「完整性基準」「內容掃描」各自防的是哪一種入口。
