提示詞注入防護

  • 03 提示詞注入與 RAG 實作｜主題 1
  • 預估學習時間：約 70–80 分鐘（4 章閱讀約 34 分鐘；章末檢核與總測驗約 25–30 分鐘；前置觀念頁另需約 10 分鐘）
  • 採用來源：LLM01:2026（Version 2026，2026-08-04）；LLM Prompt Injection Prevention Cheat Sheet（無版本，GitHub 最新提交 2026-10-22）

AI Exchange 告訴你「疊七層、假設前兩層會被突破」。這個主題往下一步：把這個原則落到 OWASP 最新的實作指引上。你會看到哪些常見做法其實只是訊號而不是邊界、真正把關的是工具邊界，以及怎麼驗證而不誇大結果。

學習目標

學完這個主題，你應該能：

  1. 為什麼沒有根治法：說明提示詞注入 (Prompt Injection) 為何沒有等價於參數化查詢 (Parameterized Query) 的做法，並用 LLM01:2026 的三個軸（投遞面、傳播行為、編碼）拆解一個情境。
    對應：第 1 章
  2. 防線的限制：判斷輸入篩選 (Input Screening)、結構化提示 (Structured Prompt)、輸出驗證、護欄模型 (Guardrail Model) 各自的限制，說明它們為何不構成安全邊界，以及它們仍有用的地方。
    對應：第 2 章
  3. 架構式控制：為有工具的 LLM 應用挑選控制（工具邊界 (Tool Boundary) 授權、最小權限 (Least Privilege)、人工確認、Rule of Two、CaMeL 的概念），並區分「降低成功率」與「限縮後果」。
    對應：第 3 章
  4. 驗證與整合：設計並回報冒煙測試 (Smoke Test) 與適應性測試而不誇大，並把防禦對應到 LLM01:2026、AI Exchange 七層與 AISVS 章節。
    對應：第 4 章

前置知識

  • 熟悉 LLM 應用開發（提示詞、工具呼叫、RAG 的運作不必再解釋）。
  • 先讀 資安前置觀念（給開發者），特別是 SQL Injection 與 Prompt Injection 的對照 和 最小權限。
  • 建議先讀 OWASP AI Exchange 主題，特別是第 4 章七層防線與第 5 章致命三要素。本主題不重講它們，而是往更細的實作層級走。

本主題三個重點

  • LLM 不區分指令與資料，所以沒有等價於參數化查詢的根治法；官方立場是防禦要靠架構，而不是攔截。
  • 輸入篩選、結構化提示、輸出驗證、護欄模型都是有用的層，但都不是安全邊界；OWASP Cheat Sheet 在 2026-10 的修訂也一路為它們加上限定語。
  • 真正把關的是工具邊界：模型提出動作，由應用程式碼依權限決定能不能做。驗證時，固定攻擊集的成績會高估防禦，回報要附分母、區間與版本。
