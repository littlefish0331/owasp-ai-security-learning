衝擊層的另外兩項，傷害的對象不同：LLM06 傷害服務與帳單（可用性與成本），LLM07 傷害被相信的內容（完整性）。它們有一個共同點：攻擊者不需要「入侵」任何東西，只要讓系統照常運作。

7.1 LLM06：成本不對稱

LLM06:2026 無限制消耗 (Unbounded Consumption) 是指 LLM 應用允許過量且不受控的推論，使攻擊者得以破壞服務可用性、造成難以承受的財務成本，或透過模型複製竊取智慧財產。官方點出的定義性特徵是成本不對稱 (cost asymmetry)：攻擊者以微不足道的代價，觸發成本高得多的運算——靠精心設計的提示詞、被盜的憑證，或被操縱的工作流程。

2025 版把它描述為「拒絕服務 (Denial of Service) 的擴充」；2026 版官方說它在清單中上升四名，原因是從業者比以往更看重資源與成本耗盡（前言的意譯）。官方列了使風險加劇的四個趨勢，這些是你判斷自家系統暴露多少的線索：

  • 官方 擴充思考與推理模型，輸出預算很大或限制不足；
  • 官方 多模態模型，單次請求的運算成本大幅提高（圖片、音訊、影片轉成大量 token）；
  • 官方 agentic 架構與工具協定（如 MCP），把一個請求放大成連鎖的下游操作；
  • 官方 共享推論基礎設施，帶來新的供應鏈攻擊面。

官方的結論是：只靠傳統的「每秒請求數」限制已經不夠，有效防禦需要 token 感知的成本控制、硬性花費上限、agent 層級的熔斷器，以及持續的成本歸屬監控。九項風險裡，下面這幾項最能說明為什麼：

7.2 LLM07：錯誤的輸出變成錯誤的行動

LLM07:2026 錯誤資訊 (Misinformation) 是指 LLM 或其應用產出不正確、不完整、無依據或誤導的資訊，且看起來夠可信，足以影響人的決策、自動化流程或 agent 的行動。官方的核心句是：風險在於不正確的輸出被信任並據以行動。因此它被描述為「系統層級的失敗」：模型輸出現在會驅動工具呼叫、產生程式碼、推斷系統狀態、授權動作、在 agent 間協調。

成因很多：幻覺、不完整或過時的上下文、薄弱的依據 (grounding)、含糊的提示、偏誤或受損的資料、誤導性摘要、未驗證的工具輸出；也可以被攻擊者刻意誘發。官方特別畫了邊界：根本原因是提示詞注入、投毒或供應鏈攻陷時，要分別引用那些條目；不安全程式碼的執行與處理歸 LLM10；幻覺出來的套件名稱被註冊成供應鏈載體歸 LLM04。這個條目聚焦的是結果的失效模式：一個錯誤的陳述，驅動了有害的決策或動作。

2025 版對應的是 LLM09:2025 Misinformation，過度依賴 (overreliance) 在 2023/24 版是獨立條目。2026 版官方在條目裡寫道：過度依賴仍是關鍵因素——人與系統常把流暢、有自信、結構良好的輸出當成權威；在 agentic 架構裡，這種過度依賴常被內建進系統設計。以下是官方七種常見風險，其中不少是「錯誤被當成狀態」：

官方的十個情境裡，有兩個特別值得讀：跨 agent 信任失敗（檢索 agent 回報某客戶「已通過身分驗證」，實際沒有，下游付款 agent 信任這個狀態並放款）；以及虛構的任務完成（agent 回報夜間備份已完成，其實從未執行，之後還原才發現沒有備份）。兩者都不涉及任何攻擊者，卻都是 LLM07：輸出被當成狀態。

7.3 一個想法，兩種防禦哲學

7.4 核心概念：在模型之外加上決定性的限制

LLM06 與 LLM07

是什麼
LLM06：推論沒有上限，導致可用性受損、成本暴增或模型被複製。LLM07：看似可信的錯誤輸出被人或自動化流程採信，並驅動行動。
為什麼會發生
LLM06：成本不對稱（便宜的輸入換貴的運算），再加上擴充思考、多模態、agent 扇出與共享基礎設施；單純的請求數限制看不到成本。LLM07：模型的輸出流暢又自信，系統設計又常把它內建為權威；在 agentic 流程中，一個 agent 的錯誤輸出變成下一個 agent 的輸入。
怎麼被利用（概念層級）
LLM06：用短而無害的提示詞讓推理模型空轉；讓長壽的 agent 工作階段緩慢累積上下文；在公開的工具庫裡放一個會造成循環呼叫的工具；或大量查詢以複製模型。LLM07：在論壇散布錯誤的修復步驟讓排障 agent 檢索後當成可信建議重複；或不需任何攻擊者，agent 就回報了從未發生的事。
怎麼防
LLM06：token 感知限制、硬性花費上限、agent 熔斷器、沙箱與監控。LLM07：先建立依據、宣告－驗證－行動、驗證工具呼叫、對高衝擊動作做執行期核准、限制爆炸半徑、持續測試。
常見誤解
「限制每秒請求數就能防住資源耗盡」（官方：一般請求限流已不足；每次都在預算內的請求也能累積成鉅額帳單）。「花費警示就是花費上限」（官方：上限必須能中止推論，警示門檻會被快速累積的工作負載追過）。「錯誤資訊只是內容品質問題」（官方：它是系統層級的失敗，輸出會驅動行動）。「模型回報完成了，就是完成了」（官方情境：agent 可能宣稱備份完成，其實從未執行）。

本章重點與自我檢核

  • LLM06 的核心是成本不對稱；擴充思考、多模態、agent 扇出與共享基礎設施使它加劇；傳統的每秒請求數限制不足以防禦。
  • LLM06 的三道防線：token 感知的限制與預估、硬性花費上限（必須能中止推論）、agent 熔斷器（步數、遞迴深度、時間、單次成本）。
  • LLM07 是系統層級的失敗：輸出被當成狀態或證據而驅動行動；不必有攻擊者也會發生。
  • LLM07 的核心模式：先建立依據；宣告－驗證－行動；工具呼叫前驗證；高衝擊動作執行期核准；限制爆炸半徑。
  • 邊界：模型擷取的側通道歸 LLM02；不安全程式碼的處理歸 LLM10；幻覺套件的供應鏈面向歸 LLM04；注入、投毒、供應鏈攻陷為根因時分別引用。
  • 我能解釋「成本不對稱」與「錢包拒絕」，並說明為什麼單看請求數看不出來。
  • 我能區分「花費警示」與「硬性花費上限」。
  • 我能說出宣告－驗證－行動的意思，並舉出它能擋下的錯誤。
  • 給我一個失效案例，我能判斷主要歸 LLM06、LLM07，還是別的條目。
